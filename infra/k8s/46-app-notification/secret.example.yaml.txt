# app-notification 비밀값 — 실제 값은 커밋하지 않는다.
#
# Secret 이 둘로 갈린 이유: FCM 자격증명은 **JSON 파일**이라 envFrom 으로 넣을 수
# 없다. `service-account.json` 은 유효한 환경변수 이름이 아니어서 kubelet 이
# 조용히 건너뛴다 — 넣었다고 믿고 넘어가기 딱 좋다.
#
# ── 1. 접속 비밀번호 (envFrom) ──────────────────────────────────────────────
#
#   kubectl create secret generic app-notification-secret \
#     --from-literal=DB_PASSWORD='...' \
#     --from-literal=MQ_PASSWORD='...' \
#     --from-literal=REDIS_PASSWORD='...'
#
#   DB_PASSWORD    = postgres-secret 의 NOTIF_APP_PASSWORD 와 같은 값
#   MQ_PASSWORD    = rabbitmq 의 RABBITMQ_NOTIF_PASSWORD 와 같은 값 (계정명 notification)
#   REDIS_PASSWORD = redis 의 requirepass
#
# ── 2. FCM 서비스 계정 JSON (볼륨) ──────────────────────────────────────────
#
# Firebase 콘솔 → 프로젝트 설정 → 서비스 계정 → 새 비공개 키 생성.
# ** 이 키 하나로 프로젝트 전체 사용자에게 푸시를 쏠 수 있다. ** 파일명 키를
# service-account.json 으로 맞춰야 마운트 경로가 application-prod.yml 과 맞는다.
#
#   scp ./키.json ubuntu@<서버>:/tmp/fcm.json
#   kubectl create secret generic app-notification-fcm \
#     --from-file=service-account.json=/tmp/fcm.json
#   shred -u /tmp/fcm.json
#
# envFrom 은 파드 생성 시점에 한 번 해석된다. Secret 을 patch 했으면
# `kubectl rollout restart deployment/app-notification` 까지 해야 반영된다.
apiVersion: v1
kind: Secret
metadata:
  name: app-notification-secret
type: Opaque
stringData:
  DB_PASSWORD: "REPLACE_ME"
  MQ_PASSWORD: "REPLACE_ME"
  REDIS_PASSWORD: "REPLACE_ME"
