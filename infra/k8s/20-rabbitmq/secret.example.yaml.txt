# 필요한 키 이름만 알리는 예시다. 실제 값은 절대 커밋하지 않는다.
#
# 확장자가 .txt 인 이유: .yaml 이면 `kubectl apply -f infra/k8s/20-rabbitmq/`
# 로 디렉터리를 적용할 때 이 파일까지 적용되어 실제 Secret 을 자리표시자
# 값으로 덮어쓴다. (Postgres 에서 실제로 겪은 사고다.)
#
# 실제 생성은 서버에서 한 줄로 실행한다. 값은 팀 비밀 저장소 참조.
# read -rsp 로 입력하면 셸 히스토리에 남지 않고 개행도 섞이지 않는다.
#
#   read -rsp "admin: " A; echo; read -rsp "core: " C; echo; read -rsp "notif: " N; echo; read -rsp "gpu: " G; echo; read -rsp "media: " M; echo
#   kubectl create secret generic rabbitmq-secret --from-literal=RABBITMQ_ADMIN_PASSWORD="$A" --from-literal=RABBITMQ_CORE_PASSWORD="$C" --from-literal=RABBITMQ_NOTIF_PASSWORD="$N" --from-literal=RABBITMQ_GPU_PASSWORD="$G" --from-literal=RABBITMQ_MEDIA_PASSWORD="$M"
#   unset A C N G M
#
# 이미 만들어져 있으면 키 하나만 더한다(2026-09-14 media 추가가 이 경우다):
#
#   read -rsp "media: " M; echo
#   kubectl patch secret rabbitmq-secret -p "{\"stringData\":{\"RABBITMQ_MEDIA_PASSWORD\":\"$M\"}}"
#   unset M
#
# ── 순서를 지킬 것 ──────────────────────────────────────────────────────────
# postStart 훅은 `set -eu` 로 돈다. RABBITMQ_MEDIA_PASSWORD 가 없는 상태에서
# 20-rabbitmq/deployment.yaml 을 apply 하면 훅이 unbound variable 로 죽어
# **RabbitMQ 파드 전체가 기동하지 못한다**. Secret 을 먼저 채우고 매니페스트를
# 나중에 적용한다.
#
# 주의
#   - 다섯 계정의 비밀번호는 서로 다르게 둔다. 같으면 계정 분리가 무의미해진다.
#   - definitions.json 은 JSON 이므로 큰따옴표(")와 역슬래시(\)는 쓰지 않는다.
#   - 값 끝에 개행이 섞이면 인증이 실패한다. wc -c 로 길이를 검증할 것.
apiVersion: v1
kind: Secret
metadata:
  name: rabbitmq-secret
type: Opaque
stringData:
  RABBITMQ_ADMIN_PASSWORD: <REDACTED>
  RABBITMQ_CORE_PASSWORD: <REDACTED>
  RABBITMQ_NOTIF_PASSWORD: <REDACTED>
  RABBITMQ_GPU_PASSWORD: <REDACTED>
  RABBITMQ_MEDIA_PASSWORD: <REDACTED>
