# [백엔드→AI팀] 편집본 S3 경로 이동 요청

안녕하세요. 백엔드에서 **편집본 영상의 S3 경로를 바꿨습니다.** AI 서버가 받는
JSON 의 **필드 구조는 하나도 바뀌지 않았고**, `base_video_key` 에 담기는 **경로 문자열만**
바뀝니다. 다만 그 경로에 S3 읽기 권한이 없으면 다운로드가 403 이 나므로 확인 부탁드립니다.

## 1. 바뀌는 것 — 편집본 S3 경로

```
(이전)  edited/{challengeSeq}/{uuid}.mp4
(이후)  private/edited/{challengeSeq}/{uuid}.mp4
```

첫 장면·선택 화면 이미지(`.jpg`)도 같은 규칙으로 `private/` 가 앞에 붙습니다.

**왜 옮겼나** — 앱이 편집본 영상을 촬영 화면 배경으로 직접 재생하게 됐습니다. 지금까지는
AI 서버만 S3 에서 내려받아 무기명 경로로 충분했는데, 앱에 주소를 주는 순간 링크만 알면
누구나 받을 수 있게 됩니다. CloudFront 서명을 붙여야 하고, **서명 검증은 `private/*`
경로에만 걸려 있어서** 키를 그 아래로 옮기는 것 말고는 방법이 없었습니다.

## 2. AI 팀에서 해주실 것 두 가지

**(1) 편집본 업로드 위치 변경**

앞으로 산출물을 `private/edited/{challengeSeq}/…` 아래에 올려주세요.
(어드민 화면에서 올리는 경우는 서버가 알아서 새 경로로 발급합니다.)

**(2) S3 읽기 권한 프리픽스 확인 — 이게 제일 중요합니다**

워커의 IAM 정책이 `arn:aws:s3:::motif-media/edited/*` 처럼 **옛 프리픽스로 한정돼
있으면 합성이 403 으로 실패합니다.** 버킷 전체(`motif-media/*`)로 열려 있으면 그대로
두셔도 됩니다.

런타임에야 드러나는 종류라, 연동 전에 한 번 확인 부탁드립니다.

> 참고: 워커는 S3 에서 직접 받으므로 **CloudFront 서명과는 무관합니다.** 서명은 앱으로
> 나가는 경로에만 붙습니다. 지금처럼 키로 S3 에서 받으시면 됩니다.

## 3. 바뀌지 않는 것

- **접수 JSON 의 필드·타입 전부 그대로입니다.** 파싱 코드는 손대실 필요 없습니다.
- `participant_mask`, `slots[].participant_mask`, `anchor`, `output_video_key`,
  `correction_enabled`, `base_duration_ms` — 이름도 의미도 동일합니다.
- 콜백(`/done`, `/failed`) 규약도 그대로입니다.

### 다만 값의 범위가 좁아진 것이 있습니다 (9/21 변경, 파싱 영향 없음)

- `participant_mask` 가 **항상 단일 비트**(1·2·4·8)입니다. 예전에는 여러 슬롯을
  동시에 지운 조합(3, 5, 7 …)이 올 수 있었는데, **편집본이 슬롯 1명당 1개로
  정리되면서** 조합이 없어졌습니다.
- 따라서 `slots[]` 도 **0개 또는 1개**입니다. 배열 형태는 그대로 둡니다.
- 편집본 제작 수량이 줄어듭니다 — 슬롯 n명이면 예전엔 `2ⁿ−1` 개였지만 이제 **n개**
  입니다(슬롯 3명 = 7개 → 3개, 4명 = 15개 → 4개).
- **전부 만들 필요도 없습니다.** 편집본이 없는 슬롯은 앱에서 선택지가 잠길 뿐,
  나머지 슬롯과 챌린지 재생은 정상입니다.

### 예시 (AI 서버 명세 §3.2 CHALLENGE)

```json
{
  "job_uuid": "b7c93b4e-0a56-4d2e-9f0d-2f6e8a54d61c",
  "job_type": "CHALLENGE",
  "attempt": 1,
  "raw_video_key": "raw/b7c93b4e-0a56-4d2e-9f0d-2f6e8a54d61c.mp4",
  "base_video_key": "private/edited/11/7d2f…e1.mp4",
  "output_video_key": "results/challenge/b7c93b4e-0a56-4d2e-9f0d-2f6e8a54d61c.mp4",
  "correction_enabled": true,
  "participant_mask": 2,
  "slots": [
    { "participant_mask": 2, "anchor": { "x": 0.72, "y": 0.34, "r": 0.0995 } }
  ],
  "base_duration_ms": 15000
}
```

`base_video_key` 앞에 `private/` 가 붙은 것 외에는 이전과 같습니다.
`output_video_key`(결과 업로드 위치)는 **바뀌지 않았습니다** — 계속 `results/…` 입니다.

## 4. 한 가지 더 — 편집본 길이를 함께 주세요

앱 촬영 타이머가 편집본 길이에 맞춰 돌아갑니다. 지금은 어드민이 업로드 화면에서
브라우저로 읽어 넣고 있는데, 산출물 전달 시 **길이(ms)를 같이 적어주시면** 옮겨 적는
과정에서 틀릴 일이 없습니다. 챌린지 원본과 ±500ms 이내여야 합니다.

문의사항 있으시면 말씀해주세요.
