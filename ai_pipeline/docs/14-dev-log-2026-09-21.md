- **근본 원인**: `output/`는 메인 FS(80GB)가 아니라 **emptyDir 볼륨 `output-disk`(medium:Disk, sizeLimit=3Gi)**. precompute가 output/에 ~2.2GB(motif_precompute 1.9G 등) 쓴 뒤 lossless `background.mp4`를 쓰려니 3Gi 초과 → ENOSPC. ## 부록 B. precompute-job 볼륨 설정 (ENOSPC 수정 반영)

⚠ 볼륨 정의는 기존 repo 배포 스크립트에 없어 여기에 기록한다. `gcloud run jobs replace <yaml>`로 관리.

| 볼륨 | mountPath | 설정 | 비고 |
|---|---|---|---|
| work-disk | `.../work` | emptyDir, **medium: Disk, 6Gi** | 실사용 ~2GB |
| **output-disk** | `.../output` | emptyDir, **medium: Memory, 16Gi** | **ENOSPC 수정**: Disk 3Gi→Memory 16Gi |
| cache-disk | `.../.cache` | emptyDir, **medium: Disk, 1Gi** | |
| model-weights | `/mnt/model-weights` | csi gcsfuse (ssafy-motif-models-us) | 가중치 |

**핵심 제약**: `medium: Disk`(ephemeral-disk) 볼륨 **총합 ≤ 10GiB**. 그래서 output은 Disk로 못 키우고 **Memory(80GB 메모리 예산, 여유 충분)** 로 전환. work+cache=7GiB ≤ 10 유지.

적용 방법:
```bash
# 현재 스펙 export → output-disk를 medium: Memory / sizeLimit 16Gi 로 수정 → replace
gcloud run jobs describe motif-precompute-job --region=us-central1 --project=ssafy-motif --format=export > job.yaml
# job.yaml 의 output-disk 블록: medium: Disk → medium: Memory, sizeLimit: 16Gi
gcloud run jobs replace job.yaml --region=us-central1 --project=ssafy-motif
```
compose-job도 동일 패턴이면 같은 수정 필요(2인/대형 출력 대비). 2인 배경은 output 사용량↑ → sizeLimit 재점검 필요.

### 10.13 ✅ 2인 precompute 완주 + SVOR 분석 (2026-09-22)
- **precompute 호출 주체 = 백엔드 API 서버**(확정).
- **light_worker 순차-read fix(`6dbc56d`)로 2인 precompute 완주**: RelightVid('light') 배경 VAE 스테이지 **22분→2.6분**(로딩 16분→~1분). → **2인 전체 85분(타임아웃)→49m40s(60분 벽 내)**, single-removal 없이. 실행 `motif-precompute-job-sbqmn`(v24). [[compose-relightvid-bottleneck]]
  - light_worker는 compose와 동일 `init_create_model`→`initialize_unet`→`load_file` 경로 → 같은 몽키패치 이식.
  - 실행 입력 트릭(AI팀 참조 안 덮어쓰게): `source_video_key`=실제 2인 영상, `base_video_key`=별도 식별자(폴더=sha256(base) 별도).
- **SVOR 분해(인물1 1084s)**: transformer 순차read **112s**(✅fix) + text encoder **218s**(cold) + **LoRA 271s(mmap, 미fix)** + 청크 9×42s **378s**. 인물2 511s(페이지캐시 warm). transformer fix는 정상, 26분의 정체는 text encoder+LoRA(로딩)+청크(연산).
- **남은 최적화 후보(전부 선택 — 이미 49.7분 완주, 오프라인 잡)**:
  - **A. LoRA 순차-read**: `remove_model_stage1/2.safetensors` 각 519MiB가 **mmap 3.6MB/s로 271s**. `lora_utils.load_file`(모듈 자체 바인딩)을 merge 루프 직전 직접 교체 → ~20s. **~4분/run 절감, 저위험, 빠른 빌드. 가장 값싼 다음 win.** 미적용.
  - **B. T5 임베딩 캐시**(`svor_prompt_cache.py`, c0789cf): 히트 시 text encoder 218s 스킵. **단** svor env에 boto3 필요(무거운 빌드) + 2회차부터만 + 미검증. A보다 열위 → 보류.
  - **single-removal**(구조적): `run_pre`가 전원 SVOR 제거 → 제거 대상 1명만. remove_id를 `PrecomputeRequest`/`run_pre`에 추가(백워드 호환) + 백엔드 협의(누가 remove_id 정하나). 2인이면 둘째 SVOR(~8.5분)+기하 절감. 60분 벽엔 이미 불필요, 긴 영상 마진/낭비제거/AI팀설계(1제거=1편집본) 정합용.

### 10.10 S3 경로 이관 대응 (백엔드 private/ 이동)
- 별도 문서 `docs/12-s3-prefix-migration-2026-09-22.md`. base가 `edited/*`→`private/edited/*`로 이동. **우리 코드 변경 없음**(경로는 요청 문자열, 폴더는 sha256 파생). 필요 조치=IAM `GET private/edited/*`(compose+precompute 둘 다, **2026-09-22 추가 완료**). 열린 질문=precompute `source_video_key` 프리픽스(API서버가 넣는 값 확인 필요). 해시 정체성 주의: precompute·compose가 동일 base_video_key 받아야 폴더 일치.

### 10.5 compose = inpainting 아님 (계약 재확인)
- inpainting/SVOR/배경생성 = **precompute 전용**. compose는 **전경(유저)만**: 검출/추적/경계보정/춤보정(MimicMotion 포즈교정)/RelightVid 20-step 재조명/배치/깊이-가림/합성. `run_post` 결과의 `background_inference`가 `disabled:…`로 시작해야 계약 준수(service.py:132에서 강제).
- **`run_post.ipynb`(AI팀 dev box) 로직 == compose job 코드** 확인함. 둘 다 `source.service.prepost.run_post(bg, fg, remove_id, gpu)` 동일 호출. 노트북은 ITZY_CAKE(141프레임/4.7s)로 end-to-end 성공(총 355.5s, geometry 26.1s, VO 크래시 없음). ⇒ 우리 컨테이너에서 깨진 건 **의존성 버전 드리프트**(pycolmap 등)이지 로직 차이 아님.
