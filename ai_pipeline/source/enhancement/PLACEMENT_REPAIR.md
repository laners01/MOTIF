## 변경

`anatomical-paired-contact-v6`은 실제 출력 시점에서 몸통과 좌우 다리의 전체 길이를 대응한다. 일반/미러 해부학적 대응을 자동 선택하지만 RGB를 좌우 반전시키지는 않는다. 기준 체형 비율을 보정하고 몸통과 일치하는 다리 관측을 사용하므로 접힌 두 다리가 스케일을 강제로 줄이지 않는다. 시간 전체의 곡률을 제한하는 희소 선형 계산으로 흔들림을 줄이며 이전처럼 작은 변화에 고정 속도 제한을 걸어 실제 크기 변화가 뒤늦게 따라가게 하지 않는다.

위치는 몸 중심을 느슨한 기준으로 유지하면서 연속 접지 구간의 발 이동을 우선한다. 배경의 대응 발도 접지 중이면 그 움직임을 전달하고, 그렇지 않으면 완만한 배경 이동을 참고한다. 들어 올린 발을 바닥에 강제로 고정하지 않는다. 바닥 추정은 완만한 이동 추세를 뺀 뒤 기존 접지 구간을 판별한다.

`correction-v7` / `temporal_version=6`은 속도 제한을 적용한 최종 시간 경로를 원본과 같은 유효 관절로 비교한다. 최소 5% 자세 오차 감소, 충분한 관절 관측, 절대 오차 한도를 만족할 때만 적용한다. 0.8–1.2배 속도, 초당 1.0배 가속도 제한, 양 끝 프레임 및 총 프레임/FPS 유지, 기존 국소 관절 보정과 선명도 유지 방식은 유지한다. 서로 다른 입력 FPS에서도 평가 자세를 실제 분수 시점에서 가져온다. 정수 프레임 계산에 생기는 부동소수점 오차(예: 31.999999999999996)는 정수로 맞춰, 바로 앞 프레임의 누락 관절 신뢰도가 섞이거나 불필요한 보간이 실행되지 않게 했다.

마지막 셀은 보정 전후 배치와 가림을 각각 계산한다. 자세 캐시도 각 RGBA 폴더별로 분리하며 기존 캐시가 입력 해시와 일치하면 재사용한다. SVOR, 음악 정렬, 깊이 모델, 배경 보존, 오디오, 조명 설정은 바꾸지 않았다.

## 검증

검증 Python은 프로젝트 지침에 지정된 video-layer만 사용했다. GPU 추론, 다운로드, 설치는 하지 않았다. 기존 출력이나 복사본을 삭제하거나 덮어쓰지 않았다.

아래는 **기존 RGBA·검출 관절을 고정한 배치 단독 비교**다. 배경과 전경에서 대응 발이 연속 접지한 구간에 한해, 합성 발의 수평 이동과 원래 배경 발의 수평 이동 차이의 절댓값 평균을 계산했다. 육안 품질 점수나 모든 프레임의 실제 3D 접지 오차는 아니다.

| 입력 | 평가 구간 수 | 이전 (픽셀/프레임) | 수정 (픽셀/프레임) |
|---|---:|---:|---:|
| AESPA | 64 | 3.29 | 0.64 |
| NMIXX | 36 | 2.80 | 0.36 |
| H2H | 36 | 3.91 | 1.45 |
| JENNY | 134 | 4.60 | 1.61 |

AESPA의 같은 관절로 비교한 박자 자세 오차는 0.1603 → 0.1344이며, 적용된 최대 시간 이동은 0.090초다. 이 오차는 정규화한 뼈 방향 차이이며 화질·안무 정답률이 아니다. NMIXX·H2H·JENNY의 계산 기록도 `work/placement_repair_20260915_094323/metrics.json`에 있다.

별도의 CPU 재합성은 기존 원본 DWPose 관절과 장면 깊이를 사용했다. 새 시간·관절 변형으로 실제 RGBA를 생성하고, 실제 RGB 샘플링 좌표를 역으로 따라 관절을 옮겨 배치·깊이 가림을 다시 계산했다. 역변환 오차가 0.75픽셀보다 큰 관절은 무효화했다. 이 진단 관절을 새 DWPose 추론 결과나 정상 자세 캐시로 등록하지 않았다. 정상 노트북 재실행은 새 전경에서 관절을 다시 검출하므로 진단 영상과 작은 차이가 있을 수 있다.

검사에는 원본/미러/지연/저신뢰도 시간 정렬, 실제 접근 후 후퇴, 접힌 다리, 누락 관절, 점프, 잘린 하체, 1·2프레임 입력, 15–120 FPS, RGBA 경계, 출력 프레임/FPS, 노트북 루트 가드와 비교 셀 배선이 포함된다. 재현 스크립트는 `check_repair.py`, `check_placement.py`, `render_repair.py`이며 위 작업 폴더에 있다. 기존 `work/dance_robustness_20260915_012438/check_robustness.py`와 `work/dance_setup/check_temporal.py`도 사용했다.

## 결과와 재실행

비교 결과의 위치는 `work/placement_repair_20260915_094323/render_review.json`에 기록한다. 각 영상의 `before_after.mp4`는 수정 전/수정 후이며, `original_vs_fixed.mp4`는 제거 전 원본/수정 합성이다. AESPA의 `dance_comparison.mp4`는 새 배치 방식에서 추가 춤 보정 전/후를 비교한다. 배경 오디오를 유지한다. JENNY의 검증 입력 `video/JENNY_background_1.mp4`에는 원래 오디오 트랙이 없어 해당 출력도 무음이다.

노트북 파일을 다시 열고 **D-3 → D-4 → E-4 → 마지막 비교 셀**을 실행한다. E-3은 선택 미리보기다. 같은 입력이면 음악 정렬·SAM 추적·SVOR·원본 깊이를 다시 실행할 필요가 없다. 추가 설치나 사용자 수동 배치 설정도 없다.

2D 관절로 측정한 접지는 실제 3D 접촉의 근사다. 원래 두 사람이 서로 다른 스텝·점프를 하거나 시점/안무가 다르면 제한된 시간·각도 보정으로 완전히 같은 동작을 만들 수 없다. 긴 가림, 잘못된 마스크/관절, 급격한 장면 전환과 화면 밖 신체에서도 완전한 복원은 보장하지 않는다. 이번 수정은 확인된 스케일 지연·골반 강제 추종·평가 점수 불일치·비교 배치 재사용 오류를 해결한다.

추가로 ±2초의 자세 시차를 탐색한 기록은 `wide_lag_diagnostic.json`에 있다. H2H에서는 약 −1.21초의 다른 미러 후보도 나타났지만, 반복 안무가 더 잘 맞는 구간을 선택한 것인지 실제 음악/동작 지연인지는 이 점수만으로 확정할 수 없다. 이를 정답으로 간주해 입력 구간을 다시 자르지 않았다. 현재 H2H에 적용된 제한 내 최대 이동은 약 0.152초이며, 안무 자체의 차이는 남을 수 있다.
