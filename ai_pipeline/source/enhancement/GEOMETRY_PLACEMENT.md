# run_depth: GVHMR 원본 기하 기반 배치

`run_depth.ipynb`의 E-3, E-4, 마지막 비교 셀은 이제
`geometry_placement.estimate(..., plan=DANCE_PLAN, gpu=int(gpu))`를 사용한다.
기존 노트북 커널에 예전 `placement`가 남아 있어도 각 셀에서 새 모듈을 직접 불러온다.
현재 배치 버전은 `gvhmr-planted-ground-v7`다. 기존 3D 배율을 유지하면서
`foot_contact.py`에서 합성에 사용하는 실제 밑창의 접지 위치를 보완한다.
수평 위치는 양쪽 발의 착지 위치를 고정된 비중으로 복원해 정한다. A와 C의
골반 기울임 위상 차이가 인물 전체의 좌우 미끄러짐으로 전달되지 않도록 한다.
발목과 신발 사이의 고정 오프셋으로 실루엣 회전을 분리한다. v7에서는 C의 접지 중
A의 이동보다 바닥 고정을 우선하고, 카메라 이동·회전·확대만 접지점에 반영한다. 양쪽 발의 근거가 부족하면
기존 기하 배치를 유지한다. C의 접지 후보는 C 카메라와 C 관측으로 판별한다.
`run_depth_v2`는 `preserve_foreground_height=True`도 함께 사용한다.
v7 검증과 비교 영상 경로는 `work/planted_feet_v7/`에 기록한다.

## 현재 준비 상태

**GVHMR 실행 환경, 공개 가중치 3개, 업로드된 SMPL-X 신체 모델의 준비를 완료했다.**
`SMPLX_NEUTRAL.npz`의 ZIP 무결성, 필수 배열 형상·유한값·스키닝 가중치,
프로젝트 내부 모델 경로 연결을 확인했다. `missing_backend()` 결과는 빈 목록이다.
SMPL-X 확인 기록은 `work/gvhmr_setup/smplx_check.json`에 있다.
시작 셀에서 필요한 파일을 검사한다. 파일이 없을 때 기존 2D 크기 계산을 3D 결과로 대체 표시하지 않는다.
설치와 다운로드는 사용자의 환경 구축 요청에 따라 진행했다. 별도의 검증은 지정된
`video-layer` Python에서 CPU/파일 검사로 수행했고, GPU 추론은 실행하지 않았다.

사용자가 업로드한 **`video/downloads/SMPLX_NEUTRAL.npz`**를 사용한다.
모델의 최종 경로를 이 위치에 연결했으므로 추가 복사 명령은 필요 없다.
다른 SMPL 모델, `.pkl`, SMPL-X 동작 데이터는 이 `.npz` 신체 모델을 대신하지 못한다.


`SMPLX_NEUTRAL.npz`는 https://smpl-x.is.tue.mpg.de/ 의 등록·다운로드 절차가 필요하다.
GVHMR 가중치에 이 신체 모델이 포함되어 있다고 가정하면 안 된다. 이 어댑터는 SAM의 선택된
인물 마스크를 사용하므로 YOLO 가중치를 통한 인물 재선택과 데모용 SMPL 메시 렌더링은 하지 않는다.

설치된 주요 버전: Python 3.10.19, PyTorch 2.3.0+cu121, torchvision 0.18.0+cu121,
PyTorch3D 0.7.6, NumPy 1.23.5, Lightning/pytorch-lightning 2.3.0, Hydra 1.3.0.
기존 `video-layer` 환경은 변경하지 않았다. 공식 requirements와 어댑터용
`scipy`, `imageio-ffmpeg`를 프로젝트 내부의 독립 환경에 설치했다.
모든 다운로드·캐시·빌드 임시 폴더는 프로젝트 안에 둔다.

설치 기록: `work/gvhmr_setup/installed_versions.json`, `requirements-lock.txt`, `weights.json`.
GVHMR 소스 커밋: `6ec3ca39336c50492c0fae65fba2fb831fc7d866`.
본체 가중치는 공식 Google Drive에서 받았다. HMR2/ViTPose는 해당 Drive의 다운로드
한도 때문에 공개 [배포 사본](https://huggingface.co/camenduru/GVHMR)에서 받았으며,
기록된 SHA-256 및 체크포인트 ZIP 무결성을 확인했다. SMPL-X는 이 사본에서 받지 않는다.
설치된 217개 패키지의 의존성 메타데이터에 충돌이 없음을 확인했다.
이 검사는 Python 3.10 환경의 실제 import/ABI 실행이나 GPU 추론 성공을 보장하지 않는다.

worker는 `.model-envs/gvhmr/bin/python` 경로 그대로 실행한다. 경로 검사 함수가
반환한 심볼릭 링크의 실제 대상을 실행하면 가상환경의 `pyvenv.cfg`를 찾지 못해
설치된 NumPy 등을 불러올 수 없다. 실행 경로에 이 문제가 있었으며 수정했다.
경로 회귀 검사: `work/gvhmr_setup/python_path_fix/check_python_path.py`.

## 동작

1. 제거 전 원본 A와 원본 전경 C의 SAM 마스크로 대상 ID를 고정한다.
2. 노트북 환경에서 원본을 디코딩하고, **분석용 복사본만** 30 FPS로 맞춘다.
   선택한 사람의 영상과 카메라 분석용 전체 장면을 따로 준비한다.
   출력 영상의 FPS·프레임 수·배경 오디오는 기존대로 유지한다.
3. 격리된 GVHMR worker가 ViTPose, HMR2 특징, SimpleVO, GVHMR를 실행한다.
   공식 데모의 영상 렌더러를 실행하지 않고 필요한 기하만 저장한다.
4. 원본 인물별 체형 beta의 시간 중앙값으로 신체 크기를 고정한다.
   배율은 카메라 초점거리/몸 중심 깊이와 고정 신체 크기로 결정한다.
   세계 좌표의 바닥을 몸 중심 아래에 투영해 배치 기준점을 구한다.
5. 원본 기하는 원본 프레임 시간으로 되돌려 캐시한다. 보정 전후 모두 이 캐시를 공유하며,
   각각 `alignment.npz`의 `baseline_frames` / `source_frames`로 기하를 가져온다.
   원본 SAM 마스크와 RGBA의 차이로 고정 크롭 원점을 복원하므로 수동 위치 입력은 필요 없다.
6. 크기·위치·접지 조건을 희소 최소제곱으로 함께 계산한다. 접지 때문에 3D 크기 기준이
   크게 바뀌지 않도록 추가 배율 보정은 ±1%로 제한한다. 이 제한은 실제 접근·후퇴 배율에
   걸리는 속도 제한이 아니다. 낮은 신뢰도의 기하는 크기 관측에서 제외한다.
7. 원본 A 마스크와 실제 보정된 C의 알파에서 좌우 밑창 위치를 관측한다.
   카메라 움직임을 제외한 좌표에서 **각 발의 접지 경로를 따로 복원**하고,
   두 발의 고정된 평균을 공통 바닥 기준으로 사용한다. 지지 발이 바뀌어도 기준이 바뀌지 않는다.
   접촉 확률·관측 신뢰도·시간상 바닥 윤곽으로 들린 발을 제외한다. 관측이 빠진 구간은
   같은 발의 앞뒤 착지 위치를 연결하고, 양 끝에서는 확인된 위치를 유지한다.
   복원한 접지점에 카메라 변환을 적용한 뒤 바닥 기준 경로를 짧게 안정화한다.
   들린 발의 위치나 3D 몸 중심의 높이를 관측 누락 구간의 바닥으로 사용하지 않는다.
8. `scene_motion.py`가 사람 마스크 밖의 장면 특징점으로 카메라의 이동·회전·확대를 구한다.
   전경 신발이 카메라 움직임을 제외하면 멈춰 있는 구간을 접지 확률과 함께 확인한다.
   프레임별 속도가 작아도 구간 전체 발 위치 변화가 크면 수평 고정에서 제외한다.
   발목에 대한 밑창/바짓단 중심의 상대 위치가 바뀌는 회전·윤곽 변화도 제외한다.
   짧은 가림 뒤 연결할 때도 전체 구간의 위치·윤곽 안정성을 확인한다.
   한 발 접지에서는 그 발의 장면 좌표를 고정하고, 양발 접지에서는 공통 이동을 고정한다.
   접지 조건을 등식으로 제거해 계산하므로 구간 끝의 약한 가중치나 ±4% 상한 때문에
   고정점이 미끄러지지 않는다. 검증된 짧은 관측 누락은 같은 고정점으로 연결한다.
   발이 떨어진 구간의 위치 보정만 부드럽게 연결하며, X/Y를 보정하고 3D 배율은 유지한다.
   전경 위쪽에 별도 인물들이 검출된 삽입 영상은 C의 카메라 추정 영역에서 제외한다.
9. E-4는 소수점 이동과 확대·축소를 하나의 affine 좌표 변환으로 합성한다.
   축소 안티앨리어싱과 premultiplied alpha를 사용한다. 알파와 깊이 가림용 관절도
   같은 변환을 사용한다. 추가 DoF/화질 맞춤 블러는 켜지 않는다.

보정 후 DWPose 캐시는 국소 가림, A/C의 좌우 대응, 실제 밑창 탐색에 사용한다. 이 관절의 길이는
전체 인물의 크기를 정하는 입력에 들어가지 않는다. 기존 `placement.py`/`anatomical.py`의
2D 배치는 다른 노트북을 위해 유지했다. `subpixel`을 지정하지 않은 합성 호출도 기존 동작이다.

## 캐시 / 재실행

- `work/gvhmr/<signature>/geometry.npz`: 원본 인물 기하.
- `geometry.json`: 입력·모델 파일 정보·실행 시간·출력 해시.
- `stage.json`: 확인된 분석용 복사본. worker가 실패해도 정상 복사본을 재사용한다.
- 합성의 `placement.json`: 사용한 원본 기하 두 경로, 시간 경로, 크롭 원점, 배치 방식.
- `placement.json`의 `contact`: 바닥 높이 경로, 지지 발, 위치 보정량과 접지 잔차.
- `contact.ground_reference`: v4에서는 `per-foot-camera-stabilized`다.
  높이 잔차는 복원한 두 발 공통 기준에 대한 내부 맞춤 오차이며, 실제 바닥 정답 오차가 아니다.
- `placement.json`의 `contact.horizontal`: 디딤 구간과 카메라 이동을 제외한 밑창 이동량.
  `correction_max_px`는 수평 접지 보정의 최대 크기다. v7의 `constraint`는
  `fixed_support_point`, `motion_reference`는 `camera`이며 `support_residual_max_px`는
  지지점 등식의 내부 잔차다. 양발 각각의 영상 픽셀이 완전히 정지한다는 지표는 아니다.
- `work/scene_motion/<signature>/camera.npz`: 원본 장면의 카메라 변환과 관측 신뢰도.

배치 계산 코드만 바뀌면 원본 GVHMR 추론을 다시 실행하지 않는다. 이전 캐시는
입력 영상·마스크·worker·모델 파일 정보·분석용 영상 형식과 출력 해시를 확인해 재사용한다.
원본 기하 캐시 버전과 배치 방식 버전을 분리했다. 분석용 영상 생성 방식을 바꿀 때는
`stage_version`도 갱신해야 한다.

같은 입력의 D-3/D-4 결과가 현재 커널에 있으면
E-4 → 마지막 비교 셀부터 실행한다. E-3은 선택 미리보기다.
새 커널이면 시작 셀부터 원래 순서대로 실행한다.
v3/v4/v5 변경은 셀이 호출하는 Python 모듈에 적용했다. 현재 E-4와 마지막 셀은 이미
모듈을 새로 불러오므로 **노트북을 다시 열거나 커널을 재시작할 필요가 없다.**
수정한 셀의 이전 출력은 지웠으며, 원래 노트북은
`work/contact_fix_20260915/backup/run_depth.ipynb`에, 생성 영상은 기존 경로에 보존했다.

## 검증과 한계

재현 스크립트: `work/geometry_placement_apply_20260915_131141/check_geometry.py`.
지정된 video-layer Python에서 GPU 없이 실행한다.

- 고정 체형/카메라에서 상체 기울기에 따른 불필요한 전역 배율 변화가 없는지 확인.

- 접지 조건이 크게 다른 경우에도 체형 배율의 ±1% 제한 확인.
- 시간 경로와 실제 전경 크롭 원점, 소수점 이동, RGB/알파 일치, 투명 영역 색 번짐 확인.

위 검증은 **알고 있는 3D 기하를 입력한 계산과 코드 연결의 검증**이다.

접지 구간의 발 위치를 제약하고 주변 움직임에 보정을 연결하는 원리는
[Footskate Cleanup](https://research.cs.wisc.edu/graphics/Gallery/FootskateSolver/footskate.html)을 참고했다.
여기서는 기존 영상 픽셀을 유지하는 2D 위치 보정에 적용하며, 논문의 3D 관절 IK를 구현한 것은 아니다.

단안 카메라 내부값은 추정값이며, 모델 추정 오차·하체 가림·급격한 컷·다른 촬영 각도·
발 주변 국소 변형에 따른 잔차는 남을 수 있다. 현재 바닥은 연속 장면의 하나의 평면으로 근사한다.
이 방식은 기존 C 픽셀을 배치하며 보이지 않던 신체나 다른 시점의 외형을 새로 생성하지 않는다.
접촉 확률이 틀리거나 두 영상의 동작·원근이 크게 다르면 두 발을 동시에 정확히 맞출 수 없다.
특히 A가 걷는데 C가 발을 고정한 구간은 A의 위치 경로를 그대로 따르면서 C의 발까지
고정할 수 없다. v7은 확실한 C 접지 동안 바닥 고정을 우선한다. 따라서 A의 이동을
접지 중인 C에 그대로 복사하지 않으며, 접지가 해제된 구간에서 위치 경로를 연결한다.
양발의 원본 픽셀 자체가 서로 다르게 움직이면 공통 이동만 제거된다. 개별 발의 변형을
모두 없애려면 다리별 관절/픽셀 변형이 필요하며, v7은 인물의 크기나 팔다리를 추가로 변형하지 않는다.
카메라 특징점이 부족하거나 가려진 발의 관측이 오래 끊기면 고정 조건을 적용하지 않는다.
접지 그림자를 생성하는 변경은 포함하지 않는다.
