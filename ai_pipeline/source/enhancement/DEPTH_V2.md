# run_depth_v2

`run_depth_v2.ipynb`를 **Python (video-layer)** 커널에서 첫 셀부터 실행한다. E-0a 입력 준비부터 새로운 추적 입력과 춤 계획을 만들어야 하므로 기존 run_depth의 중간 변수는 재사용하지 않는다. 기존 모델·패키지를 사용하며 추가 다운로드는 없다.

- E-0a: 음악 공통 구간은 기존처럼 찾는다. 전경은 원본 프레임 시각을 읽고, 필요한 구간 및 양끝의 보간 이웃만 무손실로 저장한다. 배경 FPS로 전경을 먼저 복제/생략하지 않는다. 실제 프레임 시각은 `sync.json`의 `foreground_timing.times`에 음악 시작점 기준 초로 저장한다. 첫 시각은 보간 이웃 때문에 음수일 수 있다.
- E-1b: 원본 RGBA를 그대로 남기고 별도 합성용 RGBA를 만든다. 경계 보완 v3는 원본 마스크 안팎 각 1픽셀만 부드럽게 처리한다. 배경 픽셀의 색으로 알파를 키우지 않으며, 바깥 알파는 인접 마스크에서 생기는 작은 안티앨리어싱 값으로 제한한다. 경계색은 같은 프레임의 가까운 인물 내부에서 가져와 배경색 혼입을 줄인다. 인물 내부 RGB는 그대로 둔다. 왕복 흐름과 현재 영상의 색이 일치하는 좁은 경계에만 이전 알파를 최대 30% 반영하고, 현재 마스크 범위를 다시 적용해 잔상을 제한한다. 손목처럼 두 굵은 영역을 연결하는 부분과 몸에 붙은 긴 끈 모양만 원본 알파의 85% 이상으로 보호한다. 일반 외곽의 작은 돌기에는 이 보호를 적용하지 않는다.
- 짧은 누락 복구: 가까이 떨어진 작은 부위는 최대 앞뒤 3프레임(각 0.12초 이내)의 원본 마스크를 현재 위치로 옮겨 비교한다. 양쪽의 마스크·왕복 흐름·현재 RGB가 뒷받침하며 몸과 연결되는 좁은 영역만 복구한다. 과거 RGB나 복구된 마스크를 다음 복구에 누적하지 않는다. 불확실한 영역은 유지한다. 큰 검출 누락이나 넓은 움직임 흐림을 생성해 복원하는 모델은 아니다.
- D-2/D-3: 자세 분석과 GVHMR는 기존 원본 크롭/마스크를 사용한다. 렌더링만 경계 보완본을 사용한다. 출력 시각 → 음악 상대 원본 시각 → 실제 전경 프레임 인덱스로 연결한다. 기존 속도 제한 및 시간·관절 좌표를 합친 한 번의 RGB/알파 샘플링은 유지한다. 신뢰하기 어려운 흐름은 가까운 원본을 유지한다.
- 경계 보완 업데이트: 현재 커널에 DANCE_PLAN이 있으면 **D-3 → D-4 → E-4 → 마지막 비교 셀**부터 재실행한다. D-3이 최신 경계 보완 캐시를 확인하고, 바뀌었을 때 새 춤 결과 폴더를 만들며 검증된 원본의 자세 캐시를 복사한다. 배경 SVOR·인물 추적은 재실행할 필요가 없다. 이전 RGBA/비교 결과는 보존한다. `edge_matte.json`의 `gap_repair`에 복구 프레임·픽셀 및 남은 분리 부위 프레임 수를 기록한다. 시작 동작의 추가 정렬은 이번 경계 수정 범위에 포함하지 않는다.
- E-3/E-4: `preserve_foreground_height=True`로 C의 고정된 GVHMR 추정 신체 크기를 유지하고 A가 있던 위치의 원근을 적용한다. 기존의 `A 키 / C 키` 배율 보정을 생략하므로 같은 깊이에서 A=170, C=160으로 추정되면 C는 A의 약 94.1% 높이가 된다. 추정 신체 크기는 실제 cm 측정값이 아니며, 가려짐·카메라 추정 등에 오차가 있을 수 있다. 위치·접지는 새 배율로 다시 계산하고 깊이 가림, 배경 음성, FPS와 프레임 수는 유지한다. `placement.json`에 `preserve_foreground_height`와 `estimated_height_ratio`(C/A)를 기록한다. 비교 결과는 `output/run_depth_v2/session_.../dance_comparison.../comparison.mp4`에 저장된다.
- 마지막 비교: 양쪽 모두 C의 추정 키 유지, 경계 보완과 원본 시각 기반 FPS 변환을 적용한다. 왼쪽은 추가 춤 보정 전, 오른쪽은 춤 보정 후다. 이전 키 맞춤 결과가 오른쪽에 남아 있으면 E-4 재실행을 안내한다. 키 유지 변경만 적용하려면 현재 입력이 준비된 커널에서 E-4 → 마지막 비교 셀을 실행한다(E-3 미리보기는 선택). 원본 GVHMR 캐시를 재사용하며 추가 모델·설치는 없다. E-5 조명 단계는 기존처럼 선택 사항이다.

전경과 배경의 입력 프레임 수가 다른 것은 정상이다. 원본 프레임 자체의 움직임 흐림·중복 프레임·가려진 부위는 이 변경만으로 완전히 복원되지 않는다. 시간이 실제 전경 범위를 넘어가면 기존처럼 마지막 자세를 유지하며 D-3에서 프레임 수를 표시한다.

기존 `run_depth.ipynb` 파일은 변경하지 않았다. 공용 3D 배치의 수평 안정화는 모든 호출에 적용되며, 키 유지 옵션의 기본값은 기존 A 키 맞춤이다. 원본 마스크와 경계 보완본을 분리하여 `foreground_origin`과 GVHMR 마스크 좌표를 유지한다.

접지점 고정 v7: A·C의 착지 위치로 기본 배치를 정한 뒤 C가 발을 디딘 구간은 장면 좌표에서 고정한다. 한 발이면 해당 접점, 양발이면 공통 이동을 고정하며 카메라 이동·회전·확대는 유지한다. A의 이동 경로를 따라가려는 항, 접지 끝의 약한 가중치, 보정량 상한으로 고정이 풀리던 부분을 제거했다. 짧은 검출 누락은 같은 고정점으로 이어 주고, 발이 떨어진 구간의 보정만 부드럽게 연결한다. 크기·팔다리 픽셀은 변경하지 않는다. 양발 개별 윤곽의 서로 다른 움직임까지 없애는 IK 변형은 아니다. 별도 인물이 있는 전경 위쪽 삽입 영상은 C의 카메라 추정에서 제외한다. `placement.json`의 `method`는 `gvhmr-planted-ground-v7`, `contact.horizontal.constraint`는 `fixed_support_point`다. 현재 입력이 준비된 커널에서 **E-4 → 마지막 비교 셀**을 다시 실행한다. 양쪽 영상 모두 `preserve_foreground_height=True`를 사용하고 실제 합성 기록으로 이전 결과 혼용을 검사한다.

v7 검증: `work/planted_feet_v7/check.py`. 한 발·양발 고정, 카메라 이동/확대/회전, 짧은 가림, 공중 구간, 발 회전 배제와 8개 Result 영상의 저장 기하를 CPU로 확인한다. 모델 추론은 차단하며 원본 및 기존 `comparison_v3.mp4`는 보존한다. `checks.json`에 구간별 실제 밑창 이동 폭, `render.json`에 수정 전후 재합성 영상 경로를 기록한다. 접지 검출이 불확실한 구간이나 양발의 개별 변형에는 잔차가 남을 수 있다.

검증: `work/lateral_slide_20260916/check.py`에서 골반 흔들림, 발 회전, 실제 좌우 이동, 카메라 이동, 누락 관절, 기존 점프·수직 접지를 확인했다. 최신 JENNY 저장 분석의 접지 구간 비교에서 54~66프레임의 발 이동 폭 44.36→5.18px, 97~112프레임 37.93→4.35px였다. 이는 같은 배율과 수직 위치에서 비교한 구간별 수치이며 전체 영상 품질 점수가 아니다. 접지 제약 적용은 25→109프레임이었다. 새 키 설정까지 적용한 최종 비교는 `work/lateral_slide_20260916/render.json`에 경로를 기록한다. 모델 추론 없이 저장된 깊이·자세·기하로 CPU 합성하며 이전 결과는 보존한다.

추정 키 유지 검증: `work/foreground_height_20260916/check.py`. A=170/C=160에서 화면상 높이 비율 0.941176, 변경된 배율에서 밑창 접지 유지, 원근 변화와 낮은 신뢰도 처리, 기존 기본 배치 결과 불변을 확인했다. 최근 영상의 corrected/baseline 배치를 저장된 원본 분석으로 CPU에서 계산했으며 각각 약 4.2/4.5초였다. E-3만 갱신한 경우에도 이전 E-4 영상과 새 배치가 섞이지 않도록 실제 합성 폴더의 기록을 검사한다. `checks.json`과 배치 결과를 같은 검증 폴더에 저장했다. 최종 영상 전체와 GPU 추론은 재실행하지 않았다.

검증: `work/depth_v2_setup/check.py` (지정된 video-layer Python, CPU). 30→60 / 24→30 / 30→24 / 29.97→30 시각 매핑, 소수점 음악 시작점, 가변 프레임 시각, 실제 MP4 원본 프레임 보존, 렌더링 중간 프레임, 경계 내부 RGB 불변, 캐시 재사용, 기존 v6 동작 및 노트북 셀 구문을 확인한다. `work/depth_v2_setup/latest_checks.json`, `integration.json`, `edge_examples.json`에 결과가 있다. KIOF/IVE 음악 정렬도 실제 입력으로 확인했고 필수 모델 파일 누락은 없었다. 프로젝트 검증 지침에 따라 전체 GPU 추론은 실행하지 않았다.

경계 수정 검증: `work/depth_v2_edge_fix/check.py`, `check_resume.py`. KIOF 원본 291프레임의 RGB 내부 불변, 원본 249프레임(결과 약 8.16초)의 손목 연결, 양쪽 근거가 있는 짧은 누락 복구 및 실제 가림/한쪽 근거만 있는 경우의 복구 거절, D-3에서 자세 재사용·새 결과 폴더 생성을 확인했다. 약 7.6초의 심한 움직임 흐림을 동반한 팔 누락은 신뢰할 대응이 없어 복구하지 않는다. 현재 수정으로 모든 추출 누락이 해결된 것은 아니다.

경계 노이즈 v3 검증: `work/depth_v2_noise_fix/check.py`, `preview.py`, `check_resume.py`. 저장된 291프레임에서 마스크 밖 분리 조각 픽셀(알파 > 127)은 6,414 → 0개였고 인물 내부 RGB는 동일했다. 약 5초의 경계 보정 조각 19개가 0개로 줄었으며, 저장된 자세·시간 경로로 CPU 재렌더링한 표본에서도 개선과 손목 연결을 확인했다. 가짜 배경 반짝임에 대한 알파 불변, 한 픽셀 마스크 흔들림에 대한 시간 안정화, 실제 분리된 손 보존도 검사했다. 전체 GPU 합성 영상은 재생성하지 않았다. `work/depth_v2_noise_fix/REPORT.md`에 비교 이미지와 검증 범위를 기록한다.
