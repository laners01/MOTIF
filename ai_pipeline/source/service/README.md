# run_pre / run_post

1. **run_pre.ipynb**에서 배경과 GPU를 선택하고 [2]를 실행한다. 인물 ID를 선택하지 않아도 검출된 모든 인물의 분석 자료와 인물별 제거 배경을 준비한다. 두 명이면 A만 제거한 버전과 B만 제거한 버전을 모두 따로 저장한다.
2. **run_post.ipynb**에서 같은 배경, 유저 영상, 사용할 제거 배경을 고른다. 유저 영상의 인물은 자동으로 선택·추적한다. 배경 두 명 중 한 명을 교체하면 남은 한 명이 기준 춤/가림 인물로 자동 지정된다.
3. run_post의 [2] 한 셀을 실행한다. 마지막 셀에서 배경 소리가 포함된 final.mp4와 전체 시간을 확인한다.

두 노트북의 커널은 기존 **Python (video-layer)**를 사용한다. GPU는 기존 방식대로 다중 GPU 서버에서는 1, 단일 GPU에서는 0을 기본 선택하며, 요청당 한 장만 쓴다. 모델별 기존 가상환경과 가중치를 재사용한다.

## 저장 위치

- 준비 자료: `output/background_precomputed/<원본 해시>/asset_.../manifest.json`
- 활성 준비 자료: 같은 원본 폴더의 `current.json`. 전체 준비가 성공한 뒤에만 교체한다.
- 요청 결과: `output/run_post/session_.../final.mp4`
- 시간·입력·캐시 사용 기록: 같은 폴더의 `result.json`
- 로그: `work/run_pre/session_.../pre.log`, `work/run_post/session_.../post.log`

run_pre의 저장 폴더를 지정하면 해당 프로젝트 내부 폴더에 자료를 저장한다. 예: `Result_ITZY/precomputed`. 기본 라이브러리에는 완료된 자료의 위치만 등록하므로 run_post에서 그대로 찾을 수 있다.

run_post는 준비 상태, 원본·구현·모델 버전, 저장 파일의 크기·수정 시각과 명세 해시를 확인한다. 없거나 오래되었거나 일부 파일이 사라졌으면 **준비된 값이 없습니다**를 표시하고 모델 처리를 시작하지 않는다. 전체 자산의 바이트 해시는 `service.prepared(background, deep=True)`로 추가 확인할 수 있다.

원본 전체를 일정한 FPS의 기준 영상으로 저장하고 모든 배경 분석을 그 시간축에서 수행한다. 음악 매칭 후 배경 시작점을 이 프레임 격자에 맞추며 유저 시작 시각도 같은 양만큼 옮긴다. 원본·제거 배경·마스크·관절·기하·깊이·조명 조건에 동일한 구간을 사용한다. 영상 구간을 만드는 디코딩·인코딩 시간도 온라인 시간에 포함된다.

## 온라인에서 재사용하는 것

원본 음악 특징, 인물 마스크·기준 춤·관절, GVHMR, 카메라 이동, 실제 밑창·바닥 기준, VDA 깊이와 부위별 통계, B 화질 복원이 끝난 배경, RelightVid 배경 조건·VAE latent·문장 embedding, 배경 노이즈 강도.

유저 추출·분석과 DTW·미러·관절 보정, C의 최종 배치·접지·가림, RelightVid 20 step, 그림자·최종 합성은 요청 후 계산한다. 기존 run_final의 선명도 설정과 조명·그림자·배경 오디오 흐름을 사용한다. 비교용 영상 생성은 생략한다. 배경 검출·인페인팅으로 되돌아가는 자동 대체 경로는 없다.

남은 인물의 원본 화질은 모두 보호한다. 기준 춤과 깊이 가림은 남은 한 인물을 사용한다. 배경이 세 명 이상이면 남은 ID 중 첫 인물을 자동 지정한다. 유저 인물이 여러 개 검출되면 기존 검출 신뢰도 순서의 첫 인물을 사용한다. 자동 선택된 ID는 실행 로그와 result.json에 남긴다. 현재는 남길 기준 춤 인물이 필요하므로 두 명 이상이 검출된 배경에서 사용한다. 전체 영상 분석을 잘라 쓰는 방식은 잘린 구간만 새로 분석하는 방식과 시간 문맥이 달라 결과가 완전히 같지는 않을 수 있다.

## 시간 측정 범위

`total_seconds`는 실행 함수 호출부터 준비 자료 검증, worker 시작·모델 로딩, 입력 구성, 추론, 최종 영상 저장·검사, 결과 읽기까지의 실제 경과 시간이다. 파일 업로드·사용자의 선택·결과 플레이어 표시 시간은 제외한다. 각 단계는 `timings_seconds`에 기록한다.

같은 유저 영상을 반복하면 기존 GVHMR·카메라 캐시가 재사용될 수 있다. `foreground_cache_reused`에 요청 시작 이전에 존재하던 분석 파일인지 기록하므로 첫 실행과 반복 실행을 구분해서 비교한다. 실제 처리 시간은 실행한 입력·GPU·캐시 상태에 따라 달라진다.

## 검증

프로젝트 규칙에 따라 GPU 추론·설치·다운로드 없이 CPU에서 검사한다. 서비스 테스트는 준비 상태/버전/누락 차단, 음악 특징 재사용, 부분 프레임 정렬, 배경 모델 호출 차단, 원본 오디오 보존, 최종 인코딩을 확인한다. 전체 연결 검사는 무거운 모델 호출만 대체하고 실제 자산 생성·공개·조회·보정·합성·시간 기록 경로를 사용한다. 이 테스트의 실행 시간을 실제 모델 처리 성능으로 사용하지 않는다.

실행 명령: `python -m unittest source.service.test_prepost source.relighting.test_variants source.relighting.test_composite` (프로젝트 루트에서 PYTHONDONTWRITEBYTECODE=1 설정).
