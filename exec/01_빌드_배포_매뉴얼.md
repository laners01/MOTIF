# MOTIF 빌드·배포 매뉴얼

기준일: 2026-09-28 (master `3c98bcd1`). "실측" 으로 표기한 값은 운영 서버에서 직접 확인한 것이고, 나머지는 레포의 매니페스트·빌드 스크립트 기준이다.

## 1. 시스템 개요

MOTIF 는 **안드로이드 앱 + Spring Boot 4 멀티모듈 백엔드 + GPU AI 합성 파이프라인**으로 구성된다.
백엔드는 SSAFY 지급 서버 1대(4 vCPU / 15GB RAM / 309GB, Ubuntu 24.04.4) 위의 **단일 노드 k3s** 에 배포되고,
AI 합성은 GCP Cloud Run(GPU) 에서 돌며, 영상·이미지는 AWS S3 + CloudFront 로 전달한다.

```
사용자(안드로이드 앱)
   │ HTTPS
   ▼
Traefik (k3s 내장 · hostPort 80/443 · TLS 종단, Let's Encrypt)
   │
   ├─ /api/**     ──▶ core-api (Spring :8081) ──▶ PostgreSQL · Redis
   │                    ├─ MQ job.media ───────▶ app-media (ffmpeg → HLS·썸네일 → S3)
   │                    ├─ MQ evt.notification ▶ app-notification ──▶ FCM 푸시
   │                    └─ HTTP 접수 ─────────▶ AI 접수(GCP Cloud Run) ──▶ GPU Job
   │                         ◀─ 콜백 /api/worker/v1/composite-jobs/{uuid}/done ─┘
   ├─ /admin/**   ──▶ core-api (테일넷 대역만 허용, 그 외 404)
   └─ /project/** ──▶ Jenkins (호스트 프로세스, GitLab 웹훅 전용)

미디어: 앱 ──▶ S3 presigned PUT(업로드) · CloudFront(공개 URL, private/* 는 서명 URL) ──▶ 앱
```

- HTTP 를 받는 서비스는 **core-api 하나**다. app-media·app-notification 은 RabbitMQ 컨슈머라 Service·Ingress 가 없다. 게이트웨이는 두지 않는다(ADR-0009).
- Traefik 은 hostPort 80/443 직결이라 klipper-lb 의 SNAT 이 없고, 클라이언트 원 IP 가 앱까지 도달한다. 어드민 IP 필터가 이 전제 위에 있다.
- 인증은 core-api 의 Spring Security 가 담당한다. 구글 ID 토큰을 JWKS 로 검증한 뒤 자체 JWT(HS256) 를 발급한다.
- AI 쪽에는 DB·큐·상태가 없다. 잡 상태·재시도·HLS 가공·푸시는 전부 백엔드가 관리하고, AI 는 접수 → GPU Job 1회 실행 → S3 PUT → 콜백 1회로 끝난다.
- AI 접수 URL(`AI_SUBMIT_URL`)이 비어 있으면 디스패처는 접수를 건너뛰고 잡을 QUEUED 로 유지한다. 시연에서는 `backend/tools/demo/demo_complete.py` 로 강제 완료할 수 있다(§9).

## 5. 데이터베이스 구성

단일 PostgreSQL 16 인스턴스(`deployment/postgres`) 안에 DB 1개, 스키마 2개, 계정 2개로 소유권을 나눈다.

| DB | 스키마 | 소유 계정 | 사용 서버 | 스키마 관리 | 테이블 (실측) |
|---|---|---|---|---|---|
| `motif` | `motif_core` | `core_app` | core-api, app-media | Liquibase (core-api 기동 시, changelog 22개) | 41 |
| `motif` | `motif_notif` | `notif_app` | app-notification | Liquibase (app-notification 기동 시) | 3 |

- 초기화: ConfigMap `postgres-init` 의 `init.sh` 가 **PVC 가 비어 있을 때 1회** 실행된다 — `pg_trgm` 확장, 스키마·계정 생성, 교차 접근 REVOKE, `search_path` 설정. 다시 돌리려면 PVC 를 지워야 한다(데이터 소실).
- 스키마 마이그레이션: `spring.jpa.hibernate.ddl-auto: validate` 고정, Liquibase 가 각 스키마 소유 계정으로 기동 시 실행. `databasechangelog` 도 자기 스키마에 둔다. core-api 의 startupProbe 150초는 Liquibase 예산이다.
- 데이터 볼륨: `postgres-pvc` 10Gi(local-path → 노드 로컬 디스크). 노드 소실 = 데이터 소실. S3 백업 크론은 미구현(후속).
- 접근: 테일넷 `100.106.64.43:5432` 만(Service externalIPs). 공인망 미노출.
- 실측: PostgreSQL 16.15, pg_trgm 1.6, 테이블 44개, DB 크기 11MB. 덤프·복원 절차는 `03_README.md`.

## 7. 로컬 개발 환경 (백엔드)

프로파일로 3가지 모드를 고른다(ADR-0003).

| 모드 | 프로파일 | DB | MQ · Redis | 용도 |
|---|---|---|---|---|
| 격리 | `local` (기본) | compose | compose | 기능 개발 |
| 하이브리드 | `local-remote` | compose | MQ 는 서버(테일넷), Redis 는 로컬 | 파이프라인 통합 확인 |
| 서버 | `prod` | 클러스터 | 클러스터 | k8s 전용 |

```bash
# 인프라 기동 (PostgreSQL + RabbitMQ + Redis + 스텁 AI 접수 서비스)
cd backend/local-infra && docker compose up -d --wait
#   PG localhost:5432 (motif/motif123, 앱 계정 core_app·notif_app / motif123)
#   MQ localhost:5672, 관리 UI http://localhost:15672 (motif/motif)   Redis localhost:6379 (motif123)
#   stub-worker http://localhost:18080     재초기화: docker compose down -v

# 실행 (프로파일 미지정 = local)
cd backend && ./gradlew :app-core-api:bootRun
cd backend && ./gradlew :app-notification:bootRun
cd backend && ./gradlew :app-media:bootRun        # ffmpeg 가 PATH 에 있어야 한다

# 빌드 · 테스트
cd backend && ./gradlew :app-core-api:bootJar :app-media:bootJar :app-notification:bootJar
cd backend && ./gradlew :app-core-api:test :app-notification:test :app-media:test   # 외부 의존 없음
cd backend && ./gradlew :app-core-api:localDbTest                                    # compose 필요

# 확인
curl localhost:8081/api/health       # {"status":"UP"}
```

- 필요 도구: JDK 21(없으면 Gradle 이 자동 설치), Docker + compose v2, Python 3(스모크·tools), Tailscale(하이브리드), ffmpeg(app-media).
- 구글 로그인 없이 토큰을 얻으려면 local 전용 `POST /api/dev/auth/login {"oauthSubject":"dev-1"}` 를 쓴다(운영에는 없음).
- 로컬 어드민: `http://localhost:8081/admin/login`, `admin` / `admin1234`(로컬 시드 더미).
- 로컬 S3 는 LocalStack 대신 실버킷 `dev/` 프리픽스를 쓴다 — AWS 키가 필요하다.

### 8.2 파이프라인 (`backend/Jenkinsfile`)

1. **Checkout** — `checkout scm`, GitLab 커밋 상태 `running`

7. **post** — GitLab 상태 `success`/`failed`(파드·이벤트 20줄 출력)/`canceled`

### 8.3 무중단 배포와 롤백

- core-api Deployment: `RollingUpdate maxUnavailable 0 / maxSurge 1` + `preStop sleep 10` + `terminationGracePeriodSeconds 45`(graceful shutdown 30s). 실측 0.2초 간격 517회 요청 중 실패 0.

- 수동 롤백: `kubectl set image deployment/core-api core-api=registry.local/motif/core-api:<이전태그>`. 보관 이미지는 `sudo /usr/local/bin/k3s ctr images ls -q | grep registry.local/motif`.

## 9. 배포·운영 특이사항 (트러블슈팅)

1. **`REPLACE_ME` 태그** — `40-core-api/deployment.yaml` 등 앱 Deployment 의 이미지 태그는 최초 apply 전에 사람이 실제 빌드번호로 치환한다(커밋 금지). 이후 이 파일을 그대로 재-apply 하면 태그가 `REPLACE_ME` 로 돌아가 `ErrImageNeverPull` 이 난다. 다른 필드를 고칠 때는 현재 태그를 먼저 읽어 반영한다.
2. **Secret 없이 매니페스트 apply 금지** — `RABBITMQ_MEDIA_PASSWORD` 가 없으면 RabbitMQ postStart 훅이 죽어 파드가 안 뜬다. `core-api-audit-pvc` 가 없으면 core-api 가 CrashLoopBackOff(감사 로그 어펜더 실패). JWT 비밀 2종은 32자 이상·서로 다른 값(19자로 넣어 CrashLoop 난 사고 있음).
3. **`10-postgres/secret.example.yaml`** 만 확장자가 `.yaml` 이라 `kubectl apply -f infra/k8s/10-postgres/` 로 디렉터리 apply 하면 실제 Secret 이 `<REDACTED>` 로 덮인다(실제 사고). 파일 단위로 apply 한다.
4. **AWS 키·CloudFront 개인키 주입 확인** — 서버 IMDS 가 SSAFY 계정 역할을 흘리므로 `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` 를 반드시 Secret 으로 넣는다. 빠지면 파드는 Ready 인데 S3 호출만 AccessDenied. `CLOUDFRONT_PRIVATE_KEY` 는 base64 patch 로 넣고 `printenv | wc -c` 로 길이(1704)를 확인한다(파일이 없으면 빈 값으로 성공하는 함정). 비면 보호 영상 URL 발급이 500.
5. **Swagger 공개 노출** — `40-core-api/ingress.yaml` 의 `/swagger-ui.html` `/swagger-ui` `/v3/api-docs` 세 블록은 서버에서 API 를 확인하려고 일부러 연 것이다. **심사·발표 전에 지우고 재-apply 하면 닫힌다.** 실측 2026-09-28 현재 열려 있다.
6. **개발 로그인 테스트 페이지** `/api/dev/login-test.html` 은 정적 리소스라 운영에서도 열린다(구글 로그인 확인용, 권한은 없음). 백도어 `POST /api/dev/auth/login` 은 `@Profile("local")` 이라 운영 404.
7. **어드민은 테일넷 전용** — 공인망 `/admin/**` 404 가 정상(`AdminIpFilter`, `ADMIN_ALLOWED_CIDRS=100.64.0.0/10`). ipAllowList 미들웨어는 붙이지 않는다(403 이 어드민 존재를 드러냄). 접속하려면 Tailscale 조인 + hosts 에 `100.106.64.43 j15d104.p.ssafy.io` 한 줄. 도메인이 공인 IP 로 풀리므로 테일넷에 붙었다는 것만으로는 안 된다. 끝나면 hosts 줄을 지운다(남으면 `/api/**` 도 테일넷을 탄다).
8. **AI 접수 URL 이 비어 있음** — 합성 잡이 QUEUED 로 남는다. 시연은 운영 노드에서 `python3 backend/tools/demo/demo_complete.py [job_uuid]` 로 가장 최근 미완료 CHALLENGE 잡을 미리 만든 결과 영상으로 DONE 처리한다(FCM 까지 정상 경로). 실제 AI 연동 시에는 `motif-intake` URL 을 `core-api-config` 의 `AI_SUBMIT_URL` 에 넣고 `rollout restart`.
9. **access 토큰 TTL** — 현재 30일(테스트용). 시연 전 `MOTIF_ACCESS_TOKEN_TTL=1h` 를 `core-api-config` 에 넣고 `rollout restart`.
10. **토스 키** — `test_sk_…` 이면 실카드 결제가 안 된다. 라이브 전환은 값 교체 + rollout restart.

### 11.3 주의사항

1. Job 은 **항상 exit 0** 이라 콘솔의 `succeeded` 로 성공을 판단하지 않는다. 로그의 `processing failed`/`Traceback` 유무와 콜백(`/done` vs `/failed`)로 판정한다.
2. `--max-retries=0`, `--tasks=1` 필수. 아니면 OOM 시 같은 잡이 반복 실행되고 콜백이 중복된다. 재시도 판단은 백엔드 몫이다.
3. **사전분석 선행** — 합성은 `precomputed/{챌린지}/{슬롯}/ready.json` 이 없으면 `INPUT_NOT_FOUND` 로 실패한다. 새 챌린지 슬롯(편집본)을 등록하면 반드시 `/precompute` 를 먼저 완료한다(슬롯당 약 50분).
4. task-timeout 3600초는 Cloud Run GPU Job 하드 상한이다. 백엔드는 `timeout + 5분` 뒤 미콜백 잡을 실패로 닫는다.
5. 현재 `motif-compose-job` 에 `MOTIF_SKIP_FINGERPRINT=1`(코드·가중치 지문 게이트 우회, 테스트 플래그)이 설정돼 있다. 끄려면 최종 코드로 전 슬롯 재-사전분석이 필요하다.
6. 라이선스: GVHMR 는 비상업·연구 한정, SMPL-X 는 별도 라이선스, RelightVid 는 vendor 에 LICENSE 파일 없음.

## 12. 안드로이드 앱 빌드

| 항목 | 값 |
|---|---|
| 요구 도구 | JDK 17 이상(Gradle 데몬용 JDK 21 은 foojay 가 자동 설치), Android SDK Platform 37 + Build-Tools, Android Studio(AGP 9.x 지원 버전) |
| 기기 | Android 8.0(API 26) 이상, 후면 카메라, Google Play 서비스(Credential Manager·FCM), 인터넷 |
| applicationId | `com.ssafy.motif`, versionCode 1 / versionName 1.0 |
| 빌드 타입 | 기본 `debug`/`release` 만. 난독화·서명 설정 없음(release 는 unsigned) |

필수 로컬 파일(둘 다 gitignore, 레포에 없음):

```
android/local.properties
  sdk.dir=<Android SDK 경로>
  TOSS_CLIENT_KEY=<토스페이먼츠 테스트 클라이언트 키>   # 없으면 빈 문자열로 빌드되고 결제 진입 시 안내 문구
android/app/google-services.json                     # Firebase 프로젝트의 Android 앱(com.ssafy.motif) 설정. 없으면 빌드 실패
```

Google 로그인의 웹 클라이언트 ID 는 `android/feature/signin/impl/src/main/res/values/strings.xml` 의 `google_web_client_id` 에 있다. 백엔드 `GOOGLE_CLIENT_ID` 와 같은 값이어야 한다.

```bash
cd android
./gradlew :app:assembleDebug        # → app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:installDebug         # 연결된 기기에 설치
./gradlew :app:assembleRelease      # unsigned. 배포하려면 signingConfigs 추가 또는 apksigner 서명
adb shell pm grant com.ssafy.motif android.permission.CAMERA   # 앱에 CAMERA 런타임 요청 코드가 없어 수동 허용
```

- API 서버 주소는 `android/core/network/src/main/kotlin/com/ssafy/motif/core/network/NetworkConfig.kt` 의 `BASE_URL`(`https://j15d104.p.ssafy.io/`)과 `API_HOST`(Bearer 를 붙일 호스트) 두 상수다. 다른 서버로 바꾸려면 둘 다 바꾼다.
- `android/app/src/main/kotlin/com/ssafy/motif/MainActivity.kt` 의 `DEMO_MODE`(현재 `true`)가 켜져 있으면 항상 로그인 화면부터 시작하고 로그인·온보딩은 서버 호출 없이 화면만 진행된다. 실제 흐름은 `false`.
- 런타임 권한 요청은 `POST_NOTIFICATIONS`(Android 13+) 하나다. 촬영본은 무음으로 녹화된다(`RECORD_AUDIO` 없음. 서버가 원본 오디오만 쓰므로 무방).
