# ADR-0013. 미디어는 전량 서명한다 — 공개 사본 트리를 폐기한다

- 상태: 채택
- 날짜: 2026-09-19
- 관계: [ADR-0010](0010-video-delivery.md) **D5**(CloudFront 서명을 쓰고 S3 presigned 를
  쓰지 않는다) 유지 · [ADR-0012](0012-signed-prefix-playback.md)(프리픽스 서명 + 클라이언트
  부착) 확장. **API 명세 §1.7 의 `public/` 복사 규약을 폐기한다.**

## 맥락

§1.7 은 산출물을 두 트리로 나눴다.

```
private/{challenge|motif}/{jobUuid}/   서명 필요
public/challenge/{jobUuid}/            서명 없음 — PUBLIC 게시 시 위에서 복사
```

공개 트리의 존재 근거는 하나였다 — **"공개 콘텐츠는 서명 없이 내보내 캐시를
극대화한다"**. 그 대가로 복사기 · 삭제기 · CloudFront 무효화가 필요했는데 셋 다
구현되지 않았고, 그 사이 ADR-0012 가 프리픽스 서명과 갱신 엔드포인트를 들이면서
**근거 자체가 사라졌다**. 서명 파라미터는 CloudFront 예약값이라 캐시 키에 들어가지
않으므로, 서명해도 엣지 캐시 히트율이 떨어지지 않는다.

남아 있는 문제는 셋이다.

**① `visibility` 와 키 프리픽스가 같은 것을 두 번 표현한다.** §8.9 의
`PRIVATE → PUBLIC` 은 "`visibility=PUBLIC` 인데 키는 `private/`" 상태를 만든다. 이
상태를 정상이라 선언하고 특별 취급하는 코드가 `MediaKeys` · `MediaUrlResolver` ·
`VideoRankingSnapshotJob` 에 흩어져 있다.

**② 그 영상은 HOT 에서 영구 제외된다.** `VideoRankingSnapshotJob.publicCopyReady` 가
보호 프리픽스를 떨어뜨리는데, §8.9 는 복사를 트리거하지 않으므로 "복사가 끝난 다음
틱에 들어온다"는 전제가 성립하지 않는다. 그리고 그 필터가 근거로 든 두 가지 — 무서명
URL 은 403 이고 보호 재생목록은 소유자 전용 404 다 — 는 ADR-0012 이후 **둘 다
성립하지 않는다**. `MediaUrlResolver.resolvePlaylist` 가 요청자와 무관하게 프리픽스
서명을 붙이고, `MediaPlaylistQueryService` 는 `PUBLIC` 영상에 소유자 검사를 하지 않는다.

**③ §8.10 소프트 삭제가 공개 사본을 닫지 못한다.** 산출물에 1년 `immutable` 이 붙어
있어 S3 삭제 없이는 엣지가 계속 서빙하고, 무효화 수단이 레포에 없다. 보호 경로는
`MediaPlaylistQueryService` 가 삭제분을 404 로 막지만 공개 사본에는 그 관문이 없다.

무엇보다 **무기명 공유 링크·OG 프리뷰는 제품 정책상 넣지 않는다.** 앱 내 콘텐츠를 앱
밖으로 가지고 나갈 수 있게 허용하지 않기로 했다. 무기명 URL 이 필요한 자리가 없다.

## 결정

**`visibility` 는 애플리케이션 내 공개 범위만 뜻한다. 전송 등급은 서명이 담당한다.**

- **공개 사본 트리(`public/challenge/`)를 폐기한다.** 참여 영상 산출물은 게시 여부와
  무관하게 `private/challenge/{jobUuid}/` 한 곳에 머문다.
- `visibility` 전환은 **DB 값 하나를 바꾸는 일**이다. 키를 움직이지 않고, S3 복사·삭제도
  CloudFront 무효화도 하지 않는다.
- 인가는 `MediaPlaylistQueryService` 가 **매 갱신마다** 재평가한다. 비공개 전환·삭제·
  정지가 다음 갱신(서명 TTL 10분) 안에 반영된다.
- `MediaKeys.isProtected` 는 **남는다.** 어드민이 올린 공개 카탈로그
  (`challenges/{uuid}/` · `assets/{uuid}/`)는 1단계에서 무기명을 유지한다.

### 단계

**1단계 (이 결정과 같은 티켓, 서버 단독)** — `public/` 규약 폐기. 참여 영상·모티프
결과는 이미 서명 경로를 타고 있으므로 **클라이언트 변경이 필요 없다.**

**2단계 (별도 티켓, 앱 배포 동반)** — 어드민 카탈로그와 이미지까지 서명을 확대하고
CloudFront 를 `/*` 하나로 조인다. 선행 조건 셋:

- **프리픽스 단위 서명 캐시.** RSA-2048 서명이 ~0.5–1ms 라 피드 한 장이면 수십 ms 다.
  서명은 뷰어에 묶여 있지 않아 재사용할 수 있다. 성능만이 아니라 **URL 문자열을
  안정시켜 클라이언트 이미지 캐시를 살리는 장치**다 — 매 요청 서명이 다르면 Coil/Glide
  가 만료 주기마다 전량 재다운로드한다.
- **기동 시 fail-fast.** 지금 `CloudFrontUrlSigner` 는 개인키가 없어도 warn 만 남기고
  뜬다. 전량 서명이 되면 그 상태가 전면 장애이므로 운영 프로파일에서는 뜨지 않아야 한다.
- **CloudFront behavior 와 키 롤링 절차** (인프라 파트).

## 근거

**R1. 상용 플랫폼이 노출하는 인터페이스가 정확히 이 모양이다.** Mux 는 재생 정책이
`public` / `signed` 둘뿐이고 정책을 바꿔도 스토리지가 움직이지 않는다. Cloudflare
Stream 은 비디오별 `requireSignedURLs` 플래그 하나이고 역시 오브젝트를 옮기지 않는다.
**공개범위는 플래그, 전달은 서명** — 이 분리가 제품으로 팔리는 형태다.

**R2. 대형 UGC 플랫폼은 공개 콘텐츠까지 서명한다.** YouTube 의 `googlevideo.com` URL 은
공개 영상도 `expire` + `ip` + `sig` 를 달고, Instagram/Meta 는 모든 미디어 URL 에
`oh`(서명) + `oe`(만료)를 붙여 공개 게시물도 만료시킨다. 외부에 캐시된 링크가 죽는
부작용은 그들이 **의도한 것**이고, 우리 제품 정책과 같은 방향이다.

**R3. AWS 권장과 어긋나지 않는다 — 오히려 사본 분리가 어긋난다.** CloudFront 문서와
스트리밍 보안 가이드는 공개·비공개를 버킷이나 프리픽스로 나누라고 하지 않는다. custom
policy 와일드카드(`.../movie_1/*`)가 권장이고 현재 `signPrefix` 가 그 형태다. HLS 도
"마스터를 서명하고 세그먼트는 와일드카드 경로 서명" 이 권장이다 — 조각마다 서명하면
비싸고 캐시가 파편화된다. **"게시 시 공개 프리픽스로 복사" 패턴을 권하는 레퍼런스는
찾지 못했다.**

**R4. 캐시 손실이 없다.** `Policy`·`Signature`·`Key-Pair-Id`·`Expires` 는 CloudFront
예약 파라미터명이라 사용자 쿼리스트링에 쓸 수 없고 캐시 키에서 제외된다. 서명 검증이
캐시 조회보다 먼저 일어나므로, 사용자마다 서명이 달라도 같은 오브젝트는 한 번만
캐시된다. ADR-0010 D5 가 S3 presigned 를 배제한 이유와 같은 성질이다.

**R5. 비공개 전환이 "아마도"에서 "확실히"로 바뀐다.** 사본 삭제는 무효화가 실패해도
조용하지만, 인가는 갱신마다 재평가되므로 TTL 안에 반드시 닫힌다. §8.10 삭제도 같은
관문을 지나게 되어 지금 열려 있는 구멍이 함께 막힌다.

## 결과

- **§8.9 가 단순해진다.** `composite_jobs` 조회와 키 이동이 사라지고 `visibility` 만
  바꾼다. `ParticipationVideo.changeVisibility` 에서 키 파라미터가 빠진다 — null 을
  "유지"로 해석하던 겹침도 같이 사라진다("정본을 못 찾음"과 구분되지 않았다).
- **`MediaKeys.forPublishedChallenge` 를 제거한다.** 프로덕션 호출부가 없었다 — §8.8
  게시가 아직 없어 실데이터의 `video_key` 는 언제나 `private/` 였다. 따라서 **이번
  변경으로 마이그레이션이 필요한 기존 데이터가 없다.**
- **`VideoRankingSnapshotJob.publicCopyReady` 를 제거한다.** 근거가 사라졌고, 남겨 두면
  PUBLIC 영상을 근거 없이 HOT 에서 떨어뜨린다.
- `MediaPlaylistQueryService` 의 인가 표는 그대로다. `PUBLIC` 참여 영상을 누구나 볼 수
  있는 것이 이제 예외가 아니라 **정상 경로**가 된다.
- §8.8 게시가 붙을 때 **복사기를 만들지 않는다.** 게시는 `participation_videos` 행을
  만들고 `visibility` 를 정하는 일까지다.
- **남는 약점: 서명 문자열 위임.** `signPrefix` 는 만료만 걸고 뷰어에 묶지 않으므로,
  PRIVATE 영상 URL 을 복사해 넘기면 TTL 동안 재생된다. 사본을 나눠도 똑같이 있던
  문제라 이 결정으로 나빠지지 않는다. **TTL 10분은 유지한다** — 숏폼 15초 기준 이미
  충분히 짧고(업계 가이드는 VOD 에 "콘텐츠 길이 + 여유"를 권한다), 더 줄이면 갱신
  실패로 인한 재생 끊김이 보안 이득을 넘는다. IP 바인딩은 모바일에서 셀룰러↔와이파이
  전환에 깨져 권하지 않는다(하려면 /32 가 아니라 /16 이나 세션 nonce).
- **남는 문서 부채.** §1.7 의 재생목록 리라이팅 서술(“`videoUrl` 은 core-api 를
  가리킨다”)은 ADR-0012 로 이미 낡았으나 명세에 반영되지 않았다. 이 ADR 의 범위 밖이라
  건드리지 않는다 — ADR-0012 후속으로 남는다.
