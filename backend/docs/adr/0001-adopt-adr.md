# ADR-0001. 아키텍처 결정 기록(ADR) 도입

- 상태: 승인
- 일자: 2026-09-02
- 결정자: 백엔드·인프라 (팀 회의)

## 컨텍스트

MOTIF는 운영 환경을 가정하고 설계한다. 모든 기술 선택에는 "왜 이걸 썼는가"에
대한 답이 있어야 하며, 그 답은 결정 당시의 제약과 함께 남아야 한다. 대화와
회의록에 흩어진 근거는 발표 시점에 재구성하기 어렵고, 팀원이 중간에 맥락을
따라잡기도 어렵다.

## 결정

아키텍처에 영향을 주는 결정을 `docs/adr/`에 한 파일씩 기록한다.

- 파일명은 `NNNN-영문-케밥.md`. 한글 파일명은 macOS(NFD)와 리눅스(NFC) 간
  유니코드 정규화 차이로 깨진 전례가 있어 피한다. 본문은 한국어로 쓴다.
- 형식: 상태 / 컨텍스트 / 결정 / 근거 / 검토한 대안 / 결과(트레이드오프 포함).
- 한 번 승인된 ADR은 수정하지 않는다. 뒤집을 때는 새 ADR을 만들고 이전 것을
  "대체됨"으로 표기한다 — 결정의 역사가 남는 것이 목적이기 때문이다.
- 결정의 트리거가 된 문서 버전(예: DB 명세 v0.5)을 명시한다.

## 결과

- 발표 Q&A의 방어 논리가 코드 옆에 축적된다.
- 비용: 결정마다 문서 1편. 회의(대화)에서 이미 정리된 근거를 옮기는 수준이라
  추가 부담은 크지 않다.
