# ADR-0012. 보호 등급 재생은 프리픽스 서명 + 클라이언트 부착으로 한다

- 상태: 채택 — **만료 전제는 [ADR-0017](0017-playlist-signature-lifetime.md) 이 대체**
  (10분 + 403 사후 재발급 → 2시간. 자동재생에서는 사후 복구가 성립하지 않는다.
  프리픽스 서명 + 클라이언트 부착이라는 결정 자체는 그대로다)
- 날짜: 2026-09-18
- 대체: [ADR-0010](0010-video-delivery.md) **D5** 의 구현 방식 (결정 자체는 유지 —
  "CloudFront 서명을 쓰고 S3 presigned 를 쓰지 않는다" 는 그대로다)

## 맥락

ADR-0010 D5 는 "비공개 영상은 CloudFront 서명 URL/쿠키" 까지만 정했고, 구현은
**canned policy**(URL 하나짜리 서명)로 갔다. HLS 재생목록 안의 주소는 상대 경로라
서명이 따라가지 않으므로, 조각마다 다른 서명을 박으려면 **서버가 재생목록을 다시 써야**
한다. 그래서 `MediaController` + `MediaPlaylistService` 가 생겼고 응답의 `videoUrl` 은
CDN 이 아니라 core-api 를 가리켰다.

안드로이드가 Media3 + **OkHttp Interceptor** 로 재생을 붙이기로 하면서 전제가 달라졌다.
인터셉터가 매 요청에 서명 파라미터를 붙일 수 있다면, 서버가 재생목록을 다시 쓸 이유가
없다. 다만 그러려면 **하나의 서명이 프리픽스 전체에 통해야** 한다 — canned policy 로는
불가능하다.

## 결정

**보호 등급 재생은 custom policy 로 프리픽스(`private/{kind}/{jobUuid}/*`)를 서명하고,
클라이언트가 그 파라미터를 모든 미디어 요청에 붙인다.**

- 조회 API 의 `videoUrl` 은 **CDN 절대 주소 + `Policy`·`Signature`·`Key-Pair-Id`** 다.
  core-api 경로가 아니다.
- 재생목록·조각이 전부 CDN 직통이므로 **엣지 캐시가 살아난다**. 서명 파라미터는
  CloudFront 예약값이라 캐시 키에 들어가지 않는다.
- 주소 조립은 `MediaUrlResolver.resolvePlaylist(masterKey)` 한 곳이다. 호출부가
  등급을 가르지 않는다 — 키 프리픽스가 등급이라는 규약은 그대로다.
- 서명 범위는 **영상 하나**다. 상위 경로로 넓히지 않는다 — 파라미터가 새면 그 범위가
  통째로 열린다.
- **썸네일·프로필은 바뀌지 않는다.** 단일 파일이라 canned 서명(`MediaUrlResolver.resolve`)
  이 맞고, 만료도 6시간으로 따로 잡혀 있다.

### 만료 복구 — 서명 재발급 엔드포인트

```
POST /api/v1/media/{jobUuid}/signature   (인증 필요)
→ { "query": "Policy=…&Signature=…&Key-Pair-Id=…", "expiresDttm": "…" }
```

예전 복구 경로("재생목록을 다시 받으면 core-api 가 새 서명으로 내려준다")는 **사라진다** —
재생목록도 CDN 에서 오고 같은 만료가 걸려 있다. 대신 인터셉터가 403 을 잡아 이 엔드포인트를
부르고 재시도한다.

**이것이 전환 이후의 인가 지점이다.** 재생 중에는 core-api 를 지나지 않지만 갱신은 반드시
지나므로, 환불·정지·비공개 전환이 다음 갱신에서 반영된다. 거부 판정과 404 는 기존
`MediaPlaylistQueryService` 의 것을 그대로 쓴다.

## 근거

**R1. 인터셉터 방식이 모바일에서 보편적이다.** Android `ResolvingDataSource`,
iOS `AVAssetResourceLoaderDelegate` 가 정확히 이 용도로 있는 API 다. 매니페스트
리라이팅은 광고 삽입(SSAI)처럼 조각 주소를 사용자마다 달리해야 할 때 쓰는 방식이고,
단순 보호 목적으로는 무겁다.

**R2. 엣지 캐시를 되찾는다.** 리라이팅 방식은 재생 1회당 core-api 요청 2회 +
S3 GetObject 2회가 붙고, 재생목록이 엣지에 캐시되지 않는다. 전환 후에는 0회다.

**R3. 서버에서 깨지기 쉬운 코드가 빠진다.** ADR-0010 이 경고를 둘 달아 뒀다 —
`RENDITIONS` 화이트리스트가 app-media 사다리와 어긋나면 새 화질이 404 이고,
`EXT-X-MAP` 을 리라이팅에서 빼면 재생이 시작조차 안 된다. 재생목록을 건드리지 않으면
두 함정이 모두 사라진다.

**R4. 인가 정밀도 손실은 감수 가능하다.** 요청마다 → 갱신마다로 바뀐다. 다만 서명 범위가
영상 하나이고 만료가 10분이라, 권한이 바뀐 뒤 최대 10분간 그 영상 하나가 열리는 것이
손실의 전부다.

## 결과

- `videoUrl` 계약이 바뀐다 — §4.1 · §6.1 · §8.1 · §8.2 · §11.6 · §13.3.
  **안드로이드가 인터셉터를 붙이기 전에는 재생이 되지 않는다.**
- `MediaController` 의 재생목록 두 엔드포인트와 `MediaPlaylistService` ·
  `HlsPlaylistRewriter` 는 **재생 흐름에서 빠지지만 이번에는 지우지 않는다** —
  안드로이드 전환 기간의 안전망이다. 전환이 확인되면 제거 티켓을 낸다.
- `MediaObjectStore` 의 S3 읽기 권한은 리라이팅 계층이 남아 있는 동안 계속 필요하다.
- 클라이언트는 **미디어 전용 OkHttpClient** 를 써야 한다. API 호출과 같은 인스턴스를
  쓰면 서명 파라미터가 우리 API 요청에도 붙는다.
