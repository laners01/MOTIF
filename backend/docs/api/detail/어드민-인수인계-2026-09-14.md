## 5. 알려진 함정 — 같은 걸 네 번 밟았다

**1. `:q is null` + `lower()` → 운영 500**
타입 없는 `null` 을 Postgres 가 `bytea` 로 추론해 `function lower(bytea) does not exist`.
**검색어는 호출부에서 빈 문자열로 정규화하고 쿼리에 `is null` 분기를 두지 마라.**
389·385 가 둘 다 밟았고 385 는 배포 후에야 드러났다 — 테스트가 전부 `q` 를 넘겨서.
→ **목록 API 테스트에는 "q 없음" 케이스를 반드시 넣어라.**

**2. 공용 타입 중복 생성**
네 세션이 각자 `PageResponse` 를 만들었다. 위치가 셋으로 갈려 머지에서 정리했다.
→ 공용 타입이 필요하면 만들기 전에 `backend/CLAUDE.md` 표를 확인해라.

**3. 낡은 워크트리를 읽는 것**
이 문서를 쓰면서도 한 번 당했다 — 감사 에이전트가 `S15P21D104` 워크트리를 읽었는데
그게 세션 D 브랜치라 아티스트·곡이 "없다"고 보고했다.
→ **`git worktree list` 로 어느 브랜치인지 먼저 확인해라.** `develop/backend` 는
현재 `motif-challenge` 워크트리에 있다.

**4. Liquibase property 와 Spring Binder**
`ADMIN_SEED_HASH` 미주입 시 Binder 가 placeholder 를 예외 없이 통과시켜
`'${ADMIN_SEED_HASH}'` 문자열이 DB 에 저장됐다(앱은 정상 기동). DB CHECK 로 막아뒀다.
→ 설정값이 필수라고 믿지 마라. 실제로 빈 DB 로 한 번 돌려봐라.
