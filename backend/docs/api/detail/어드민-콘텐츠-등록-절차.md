# 어드민 콘텐츠 등록 절차

**2026-09-21 · 대상: 백엔드 팀 · 기준: 어드민 명세 v0.5 §3.5~3.8**

어드민 화면에서 **무엇을 어떤 순서로** 등록하는지 적는다. 순서를 어기면 앞 단계가 없어서
선택지가 비어 있거나, 등록은 되는데 앱에서 안 보인다.

---

## 0. 의존 순서 — 이 순서를 어기면 막힌다

```
소속사 ─▶ 그룹 ─▶ 아티스트 ─┬─▶ 곡 ─▶ 챌린지
                            └─▶ 에셋(모티프)
```

| 만들 것 | 먼저 있어야 하는 것 | 없으면 |
|---|---|---|
| 그룹 | 소속사 | 등록 폼의 소속사 선택지가 비어 있다 |
| 아티스트 | 소속사 (그룹은 선택) | 같음 |
| 곡 | 아티스트 | 가수 선택지가 비어 있다 |
| 챌린지 | 아티스트 + 곡 + **AI 편집본** | 아래 §3 참조 |
| 에셋 | 아티스트 | 아티스트 선택지가 비어 있다 |

**솔로 아티스트는 그룹을 건너뛴다.** 그룹은 선택 입력이다.

---

## 1. 소속사 · 그룹 · 아티스트

`/admin/orgs` → 소속사·그룹을 한 화면에서 만든다.
`/admin/artists` → 아티스트 등록. 소속사는 필수, 그룹은 선택.

아티스트 프로필 이미지는 **여기서 올린다.** 챌린지 슬롯의 동그란 얼굴(§7.2 선택 화면)이
이 이미지를 그대로 쓴다 — 비어 있으면 앱에서 원 안이 빈다.

---

## 2. 곡 등록

`/admin/songs`

| # | 할 일 | 비고 |
|---|---|---|
| 1 | **가수(아티스트) 선택** | 없으면 아티스트부터 |
| 2 | 곡 제목 입력 | |
| 3 | 등록 | |

곡은 챌린지가 참조만 한다. 음원 파일을 올리지 않는다 — **제목과 가수뿐이다.**

---

## 3. 챌린지 등록 — 가장 복잡하다

`/admin/challenges/new`

### 3-0. 시작 전 준비물

**AI 팀 산출물이 먼저 있어야 한다.** 어드민은 파일을 올리고 좌표를 옮겨 적는 일만 한다.

| 준비물 | 개수 | 누가 |
|---|---|---|
| 원본 영상 MP4 | 1 | 촬영·편집 |
| **편집본 MP4** — **그 슬롯의 인물 한 명만** 지운 영상 | **슬롯당 1개** (최대 4) | **AI 팀** |
| 첫 장면 JPG — 촬영 가이드 배경 | 편집본마다 1 | AI 팀 |
| 선택 화면 JPG — 그 슬롯을 골랐을 때 보이는 이미지 | 편집본마다 1 (생략 가능) | AI 팀 |

**조합 편집본은 만들지 않는다**(2026-09-21 확정). 사용자가 고르는 것은 **함께할 아티스트
한 명**이라 2명 이상을 동시에 지운 영상은 쓸 일이 없다. 슬롯 3개면 편집본도 3개다
(예전엔 `2³−1 = 7` 개였다).

메인 아티스트도 슬롯에 넣지만 **메인을 지운 편집본은 만들지 않는다** — 그 슬롯은 편집본을
비워 두면 되고, 앱이 `selectable: false` 로 받아 선택지에서 잠근다(§7.2).

> **편집본 없이도 등록은 된다.** 전부 비우면 "표시 전용" 챌린지가 된다 — 앱 목록에는
> 보이지만 어느 슬롯도 고를 수 없다. 사용자가 그래도 보내면 404
> `EDITED_CHALLENGE_NOT_FOUND` 다. AI 산출물이 늦을 때 임시로 쓰고, 나중에
> 상세 화면의 슬롯 행에서 파일만 올리면 된다(§3.7.6 — 슬롯 교체가 아니다).

### 3-1. 원본 영상 (화면 1번 칸)

1. 파일 선택 → 브라우저가 **길이·해상도를 읽어** 서버에 함께 보낸다
2. presign 발급 → S3 직행 업로드가 **자동으로** 진행된다
3. 업로드가 끝나면 영상이 화면에 뜬다

| 제약 | 값 |
|---|---|
| 방향 | **세로** (height > width). 가로면 400 `MEDIA_INVALID` |
| 길이 | 60초 이하 |
| 형식 | MP4 · MOV |

**썸네일 시각**을 슬라이더로 고른다. 비워두면 1.5초 지점이다 — 첫 프레임은 페이드인·
모션블러가 흔해서 피한다. 이미지를 따로 올리지 않고 **워커가 원본에서 그 지점을 뽑는다.**

### 3-2. 기본 정보 (2번 칸)

메인 아티스트 · 곡 · 소개글을 고른다.

**메인 아티스트는 등록 후 바꿀 수 없다**(R1 — 원본 교체 금지). 잘못 골랐으면 삭제 후
재등록이다. 곡과 소개글은 나중에 상세 화면에서 고칠 수 있다.

### 3-3. 슬롯 · 편집본 (3번 칸)

**슬롯 = 사용자가 자기 얼굴로 바꿔 넣을 수 있는 자리.** 영상에 나오는 사람 중
교체 대상만 넣는다. 0~4개.

**편집본이 같은 행에 있다**(2026-09-21) — 편집본이 슬롯 1개당 1개라 조합 매트릭스가
없어졌다. 한 행 = 한 사람 = 그 사람을 지운 영상.

1. `슬롯 추가` → 행이 생긴다
2. 아티스트 선택
3. **앵커** 입력 — 영상을 보면서 그 인물 위를 클릭하면 좌표가 찍힌다
4. 그 행에 **편집본 3종**을 올린다 — 영상 · 첫 장면 · 선택 화면

| 규칙 | 내용 |
|---|---|
| **순서가 곧 마스크** | 화면 **좌 → 우** 순서로 넣는다. 1번째=1, 2번째=2, 3번째=4, 4번째=8 |
| **메인 아티스트도 슬롯에 넣는다** | 2026-09-21 변경. 앱 선택 화면에 원이 뜨려면 슬롯에 있어야 한다. 다만 **메인은 지워지지 않으므로** 그 행의 편집본은 비워 둔다 |
| 중복 불가 | 같은 아티스트를 슬롯 둘에 넣을 수 없다 |
| 앵커 범위 | `0 ≤ x,y ≤ 1` · `0 < r ≤ 0.5` (썸네일 대비 비율) |
| **영상·첫 장면은 짝** | 둘 다 올리거나 둘 다 비운다. 한쪽만 올리면 400 |
| 선택 화면만 올리기 불가 | 편집본 없이 선택 화면만 있으면 400 — 고를 수 없는 그림이 남는다 |

**순서를 틀리면 편집본과 어긋난다.** 왼쪽 사람의 행에 오른쪽을 지운 영상을 올리면,
사용자가 왼쪽을 골랐을 때 오른쪽이 지워진 영상이 나온다. **등록 후에는 화면으로
확인할 방법이 없으니** 이 단계에서 좌→우와 "이 행의 영상은 이 사람을 지운 것"을 지킨다.

| 검증 | 실패 시 |
|---|---|
| 아티스트 중복·앵커 범위·편집본 키 짝 | 400 `PARTICIPANT_INVALID` (위반 목록을 `data` 로) |
| 편집본 길이 = 원본 ±500ms | 409 `EDITED_DURATION_MISMATCH` |
| S3 에 파일이 실제로 있는가 | 409 `MEDIA_NOT_UPLOADED` (부재 키 목록을 `data` 로) |

### 3-5. 등록 (4번 칸)

1. **`사전 검증`** 을 먼저 누른다 — DB 를 바꾸지 않고 문제만 모아서 보여준다(§3.7.8)
2. 문제가 없으면 **`등록`**

**등록은 원자적이다.** 챌린지·슬롯·편집본이 한 트랜잭션이라, 편집본 하나가 잘못되면
챌린지 행도 남지 않는다. 중간에 실패해도 찌꺼기가 없다.

### 3-6. 등록 직후 — 후처리를 기다린다

등록하면 `job.media` 가 발행되고 **app-media 가 HLS 를 만든다**(수십 초).

- 그 전까지 상세 화면의 썸네일은 "생성 중" 으로 뜬다
- **썸네일이 나와야 앵커를 찍을 수 있다** — 앵커는 썸네일 위 좌표다
- `video_key` 가 `.mp4` → `master.m3u8` 로 바뀐다

### 3-7. 상세 화면에서 고칠 수 있는 것

`/admin/challenges/{challengeSeq}`

| 항목 | 가능 | 비고 |
|---|:---:|---|
| 곡 · 소개글 | ✅ | §3.7.4 |
| 슬롯 앵커 (x·y·r) | ✅ | 행을 고르고 썸네일 클릭. 합성 잡이 참조 중이어도 된다 |
| 편집본 파일 3종 | ✅ | 슬롯 행에서 파일을 고르면 교체된다(§3.7.6) |
| **비어 있던 슬롯에 편집본 채우기** | ✅ | 2026-09-21 추가. 영상과 첫 장면을 **둘 다** 골라야 저장된다 |
| 슬롯 아티스트 | ✅ | 슬롯 표에서 고르고 `슬롯 저장` — 바꾼 행은 편집본이 비워진다 |
| 슬롯 **추가** | ✅ | `슬롯 추가` → 맨 뒤에 붙는다. 앵커·편집본은 저장 뒤에 채운다 |
| 메인 아티스트 · 원본 영상 · 길이 | ❌ | 불변. 삭제 후 재등록 |

**슬롯 저장은 구성을 통째로 다시 쓴다**(§3.7.5). 편집본 파일은 그대로 두고 행 seq 만
새로 난다. **합성 잡이 그 슬롯을 쓰고 있으면 409** `EDITED_IN_USE` 로 막힌다.

**아티스트를 바꾼 행은 편집본이 비워진다** — 옛 영상은 이전 사람을 지운 것이라 새 주인에게는
틀린 베이스다. 저장 뒤 그 행에 새 파일을 올린다.

슬롯을 추가할 때 **맨 뒤에 붙는 이유**가 있다. 순서가 곧 마스크(1·2·4·8)라 중간에 끼워
넣으면 뒤 슬롯이 한 칸씩 밀리고, 이미 합성된 영상이 가리키던 자리가 다른 사람이 된다.

## 4. 에셋(모티프) 등록

`/admin/assets/new`

| # | 할 일 |
|---|---|
| 1 | 아티스트 선택 |
| 2 | 제목 · 설명 |
| 3 | 영상 파일 — presign → S3 자동 업로드 |
| 4 | 종류 선택 — `NORMAL` · `PREMIUM` · `SECRET` |
| 5 | 등록 |

챌린지와 달리 **슬롯도 편집본도 없다.** 영상 하나로 끝난다.
등록 후 app-media 가 HLS·썸네일을 만드는 것은 같다.

가격은 별도 화면이다 — `/admin/prices`. 에셋을 먼저 만들고 거기서 값을 매긴다.

## 5. 자주 막히는 곳

| 증상 | 원인 |
|---|---|
| 선택지(아티스트·곡)가 비어 있다 | 앞 단계를 안 만들었다. §0 의존 순서 |
| 400 `MEDIA_INVALID` | 원본이 가로거나 60초를 넘었다 |
| 400 `PARTICIPANT_INVALID` | 아티스트 중복·앵커 범위 위반, 또는 편집본 영상/첫 장면을 한쪽만 올렸다. `data` 에 위반 목록 |
| 409 (부재 키 목록) | S3 업로드가 끝나기 전에 등록을 눌렀다 |
| 썸네일이 계속 "생성 중" | app-media 후처리 실패. `dlq.job.media` 와 app-media 로그를 본다 |
| 앱에서 슬롯이 잠겨 있다 | 그 슬롯에 편집본이 없다(§7.2 `selectable: false`). 상세 화면 그 행에 파일을 올린다 |
| 앱에서 슬롯을 고르면 404 | 위와 같은 상태인데 클라이언트가 `selectable` 을 안 보고 보냈다 |
| 409 `EDITED_IN_USE` | 그 슬롯을 쓰는 합성 잡이 있다. 앵커·파일 교체는 되지만 슬롯 구성 교체는 막힌다 |

## 6. 시연용 최소 코스

처음부터 끝까지 한 번 태우려면 이 순서가 가장 짧다.

1. `/admin/orgs` — 소속사 1개
2. `/admin/artists` — 아티스트 2명 (**프로필 이미지 필수** — 슬롯 원에 쓰인다)
3. `/admin/songs` — 곡 1개
4. `/admin/challenges/new` — 슬롯 1개 + 편집본 1개로 등록
5. 썸네일 생성을 기다렸다가 상세에서 **앵커 찍기**
6. 앱에서 그 챌린지로 촬영 → 합성 → 게시

**슬롯 1개로 시작하는 걸 권한다.** 편집본이 1개면 되고, 그것만으로 촬영부터 게시까지
전 경로가 돈다.
