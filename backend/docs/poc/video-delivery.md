## 배경

피드는 참여 영상(15~60초, 9:16)을 연속 스와이프로 소비한다. 현재 설계는 합성 워커가 단일 MP4 를 S3 에 쓰고 CloudFront 로 내려주는 것까지다. "다음 영상이 얼마나 빨리 뜨는가"와 "그 대가로 트래픽을 얼마나 쓰는가"는 아직 결정된 바 없다. 이 문서는 그 결정에 앞서 "무엇을 얼마로 보면 합격인가"를 고정한다 — 없으면 결과표를 놓고 해석 싸움이 난다.

## 진행 원칙

안드로이드 없이 백엔드가 헤드리스로 전략을 비교하고 결정한다. 안드로이드는 확정된 결과(티켓 6 인계 문서)를 그대로 구현하며, 이 PoC 를 위한 별도 화면·계측은 두지 않는다.

```
TTFF ≈ RTT×왕복수 + 첫프레임바이트÷대역폭 + 디코더초기화
       └── 전략이 바꾸는 항: 헤드리스 측정 ──┘  └ 단말 상수, 전략 무관 ┘
```

전략 간 순위는 네트워크 항에서 갈리고, 그 항은 ffmpeg 클라이언트 + `tc netem` 으로 재현된다. 단말 상수는 어떤 전략이든 같으므로 결정에 영향이 없다.

**영상 소스**: 팀 제공, 재인코딩 없음. 파일 특성(moov 위치·GOP·비트레이트·길이)은 `probe`(티켓 4)가 기록해 결과 해석에 쓴다. 유일한 가공은 faststart **remux**(`-c copy`, 화질 변화 없음) — 원본에 moov 가 뒤에 있을 때만, A/B 대조군으로.

**검증 대상 전략** (배타적이지 않다 — 층이 다르다)

| 층 | 전략 | 이 PoC 에서 |
|---|---|---|
| 인코딩 | faststart, GOP, 비트레이트 | **관찰만.** faststart 만 remux 로 A/B |
| 전송 | progressive MP4 + HTTP Range (CDN) | 그대로. HLS 는 조건부(티켓 7) |
| 프리페치 정책 | 앞 N개 × 첫 T초 | N·T 스윕 — 이게 주 실험 |
| 화질 적응(ABR) | HLS 다중 렌디션 | **기본안 제외.** 기준 미달 시에만 |

## 네트워크 프로파일 (확정)

2종: Wi-Fi(기준선) / LTE 양호(20Mbps·50ms)

## 시청 행동 모델 (확정)

세션 시뮬레이터 입력. 30개 피드, 시청 시간 분포 {3초 스킵 40%, 절반 30%, 완시청 30%}.

## 제공 영상 목록 (확정)

30개. 15~60초 구간에 걸쳐 준비하고, 실제 파일의 길이·비트레이트 분포는 `probe`(티켓 4)로 기록한다. 특성이 제각각이면(비트레이트 편차 큼) 결과를 특성 구간별로 묶어 본다.

## 트래픽 모델 `실측 반영`

**계수 갱신.** 제공 영상 31개의 실측 평균 비트레이트는 **3.35Mbps**다(원본, 1080p 위주).
당초 예시로 쓰던 2.5Mbps 가 아니다. 렌디션은 720p 0.78Mbps · 480p 0.47Mbps.

**식 수정 — 초판 식은 프리페치분을 이중계산한다.**

```
초판(틀림):  세션 = Σ(시청초 × bytes/초) + 스와이프수 × N × T × bytes/초
```

프리페치한 앞 T초는 그 아이템을 시청하면 **시청 바이트에 이미 포함**된다. 받아둔
구간을 다시 받지 않기 때문이다. 위 식은 시청까지 이어진 아이템의 프리페치분을
두 번 센다. 실측에서 T 가 커질수록 오차가 커지는 것으로 확인됐다(N=1 −6%,
N=3×T=3 −41%).

```
수정:  세션 = Σ(시청초 × bytes/초) + (미시청 프리페치 아이템 수) × N × T × bytes/초
```

두 번째 항은 결국 **프리페치 낭비**와 같다. 실측 낭비율은 정책에 따라 1.5~10.6%다.

**실측 기준 예시** (14개 시청 세션, `N=2,T=1.5`):

| 화질 | 비트레이트 | 세션 egress | 시청 아이템당 |
|---|---|---|---|
| 원본 | 3.35Mbps | 56.6MB | 4.04MB |
| 720p | 0.78Mbps | 17.1MB | 1.22MB |
| 480p | 0.47Mbps | 10.1MB | 0.72MB |

## 완료 조건

이 문서가 머지되면 이후 티켓(2, 4, 5)은 여기 정의된 지표·목표만 참조한다. 네트워크 프로파일·시청 행동 모델·제공 영상 목록·트래픽 모델은 위 내용으로 **확정**. 지표별 목표치(위 표의 "목표" 열)만 **제안값이며 팀 회의에서 확정**한다.

## 측정 후 드러난 보완 사항 `실측`

설계 시점에 빠져 있던 것들이다. 다음 PoC 설계 때 같은 함정을 피하기 위해 남긴다.

1. **시청 행동 모델에 이탈이 없었다.** 이탈이 없으면 피드를 끝까지 소비해
   프리페치 낭비가 **구조적으로 0** 이 된다. 그러면 N·T 를 키울수록 유리하기만
   해서 주 실험이 성립하지 않는다(최적값이 N=∞). 스와이프당 이탈 확률 0.05 를
   제안값으로 넣어 측정했다 — **팀 확정 필요**.
2. **확정 프로파일 2종으로는 ABR 판정 게이트가 열리지 않는다.** wifi·lte_good 은
   2.5Mbps 영상에 8배 이상 여유라 재버퍼가 나올 수 없다. `lte_poor`(4Mbps)와
   `3g`(1.5Mbps)를 넣어야 화질 사다리 판단이 가능하다.
3. **프리페치 이득을 재는 지표가 없었다.** TTFF 는 프로파일별로만 정의돼
   정책이 바뀌어도 값이 변하지 않는다. 실시간 재생 모드의 **멈춘 시간 차이**로
   잡아야 한다.
4. **TTFF(net) 정의에 도구 상수가 섞여 있었다.** `ffmpeg` 실행 시간에는 프로세스
   시작·디코더 초기화가 31~49ms 포함된다. 그 상태로 p50<200ms 목표를 걸면 도구
   오버헤드까지 판정에 들어간다. 셰이핑을 끄고 잰 값을 빼야 순 네트워크 항이 된다.
5. **재버퍼 지표를 "스톨 횟수"로 두면 모델에 좌우된다.** 시뮬레이터의 조각 단위를
   바꾸면 값이 바뀐다. **멈춘 누적 초**를 같이 기록해야 비교가 성립한다.
